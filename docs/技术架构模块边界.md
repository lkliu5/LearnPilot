# 智学中枢技术架构模块边界

> TASK-001 基础工程整理产物。本文只定义现有后端模块的职责与依赖方向，不改变接口契约。

## 1. 模块职责

| 目录 | 职责 | 不应承担 |
|---|---|---|
| `app/api/` | HTTP、SSE、WS 入参校验，鉴权依赖，响应信封 | 复杂业务规则、直接拼装模型 Prompt |
| `app/services/` | 用例编排、事务边界、领域服务 | Web 协议细节、全局配置定义 |
| `app/agents/` | 单个 Agent 的输入、决策和结构化输出 | 路由、数据库生命周期管理 |
| `app/workflows/` | LangGraph 状态与 Agent 协作流程 | HTTP 响应构造、前端展示逻辑 |
| `app/rag/` | 切片、嵌入、检索、重排和接地 | 用户认证、学习旅程规则 |
| `app/models/` | SQLAlchemy 持久化实体 | API 请求响应模型 |
| `app/schemas/` | Pydantic 边界模型 | 数据库查询与业务副作用 |
| `app/core/` | 配置、日志、安全、数据库、LLM 网关等横切能力 | 具体页面或单一业务用例 |

## 2. 允许的依赖方向

```text
api -> schemas + services + core
services -> models + agents/workflows/rag + core
workflows -> agents + rag + core
agents -> rag + core
rag -> core
models/schemas -> 基础库（不得反向依赖 api/services）
```

跨模块调用优先通过公开函数或服务接口完成。禁止 `models`、`schemas`、`core` 反向导入 API 路由，也禁止业务服务依赖前端资源结构。

## 3. 配置与日志约定

- 环境配置统一定义于 `app/core/config.py`，业务模块不得直接读取环境变量；操作系统路径探测等非业务环境信息除外。
- 密钥只经 Settings 或用户模型配置服务注入，不写入日志。
- 应用日志统一使用 `logging.getLogger(__name__)` 或稳定的 `app.*` 名称。
- 日志自动携带 `traceId`，并对手机号、邮箱和常见 API Key 脱敏。
- 请求日志只记录方法、路径、状态和耗时，不记录 Authorization、请求正文或用户隐私。

## 4. 后续变更规则

新增模块应先归入上述职责之一。确需改变依赖方向时，应通过独立任务评审；TASK-001 不进行现有业务文件搬迁或大规模重构。
