## 会话一 · 生成产物落库 + 资源库 CRUD（数据层地基，先做）

═══════════════════════════════════════════════════════════════
# 角色
资深全栈工程师。项目已联调，禁改既有接口签名。本会话把生成产物落库，让资源库真正管理资产（不再每次重新生成）。

# 背景问题
现在"我的资源库"只存生成日志(GenerationLog)、不存产物，点"查看"文档类资源时会重新跑一次 RAG+大模型生成（~25s、内容可能不一致、部署后会大量重复生成）。要改为：产物落库、查看直接读、重新生成变显式可选。

# 先查并报告
GenerationLog 现在存什么字段？各类型产物（讲义 markdown/图解 mermaid/思维导图/练习题/闪卡数据/视频）现在怎么存/怎么取？视频是否已落盘（videoUrl）？

# 任务
1. **产物落库（存 DB）**：
   - 生成时把产物**实际内容**存入 DB（讲义 markdown、图解 mermaid 源码、思维导图数据、练习题、闪卡数据等文本类产物存数据库；视频沿用已落盘的 mp4 文件 + videoUrl）；
   - 可在 GenerationLog 上扩展产物字段，或新增关联的产物表（artifact），按需设计；产物与生成记录关联。
2. **查看直接读产物**：资源库/文档学习"查看"→ 直接读已存产物渲染，**不再调用生成接口重新生成**（消除 ~25s 等待与内容不一致）。
3. **重新生成变显式可选**：加"重新生成"操作——用户主动点击才重跑生成并**更新**已存产物（覆盖旧产物、刷新时间）。默认查看不触发生成。
4. **资源库增删改查（CRUD）**：
   - 查（读产物，已上条）、删（已有删除，确认归属）、
   - **改**：重命名（改标题）、重新生成（更新产物）；
   - 增（生成时自动记录，已有）。
   - 新增/补充接口（重命名、重新生成、读产物）套统一信封、追加文档、按 user 校验归属。
5. 内置课程资源同样受益（若之前也有重复获取，统一为读产物）。

# 约束
- 不改既有接口签名（新增仅追加）；不改内置画像/诊断/路径/掌握度；向量库隔离不变；mock 兜底（无 Key 有确定性产物）。
- 注意 DB 产物大小合理（大文本存 DB 可接受，视频等大文件仍用文件系统 + URL）。

# 验证（截图/实测）
1. 生成某资源 → 产物入库；点"查看" → 直接读产物秒开、**后端 0 次生成调用**、内容与生成时一致；
2. 点"重新生成" → 显式重跑、产物更新、时间刷新；
3. 资源库可重命名、删除（确认归属）；
4. 部署视角：反复查看不再重复生成、不堆积；内置功能无回归、全量测试通过、tsc 干净。

# 输出
现状 + 产物存储设计 + 改动文件清单 + 接口文档增量 + 验证结果 + 红线自检。完成即停。

## 会话二 · 文档学习生成体验：进度反馈 + 大预览框可操作

> 会话一（产物落库）验证后再做，本会话预览直接读已存产物。

═══════════════════════════════════════════════════════════════
# 角色
资深前端工程师。项目已联调，禁改既有接口签名。本会话优化文档学习右栏生成的交互体验。

# 任务
1. **生成进度/状态反馈（需求A）**：文档学习右栏点击生成某类型后，显示明确的进度/状态（生成中…/进度，而非干等转圈无反馈）；生成完成后状态变"已生成·点击查看"。视频等长任务复用已有任务轮询/进度。
2. **大预览框 + 框内可操作（需求C）**：点击查看/生成完成后，内容在一个**较大的预览框/弹层**里展示（不是小区域挤着或要滚很久），看得舒服；预览框内可直接操作：
   - **下载**（复用现有各类型下载 md/pdf/svg/png/mp4/代码）；
   - **重新生成**（复用会话一的显式重新生成，更新产物后预览刷新）；
   - **编辑**（至少支持重命名标题；若成本可控，讲义类可支持简单文本编辑并保存回产物——评估后决定，不强求全类型编辑）。
   - 预览内容直接读会话一已落库的产物，不重新生成。
3. 预览框布局清晰、大而舒适、深浅主题正常、响应式合理；讲义公式/图解/表格等复用现有论文级渲染管线（KaTeX/mermaid/gfm）。

# 约束
复用现有渲染/下载/生成/重新生成能力与产物；不改接口签名（新增仅追加）；不动内置课程；mock 兜底。

# 验证（截图）
1. 生成时有进度/状态反馈、不干等；
2. 查看/生成完 → 大预览框展示、内容用论文级渲染（公式/图解正常）；
3. 预览框内可下载、可重新生成（刷新产物）、可重命名；
4. 深浅主题正常、响应式合理、tsc 干净、0 console error、无回归。

# 输出
改动文件清单 + 验证结果 + 红线自检。完成即停。
═══════════════════════════════════════════════════════════════

## 提示（给你人看）
- 会话一是地基：产物落库后，"查看=读、重新生成=可选"，这是面向真实部署的正确架构（不重复烧 API、内容一致）。验收死盯"查看时后端 0 次生成调用"。
- 会话二依赖会话一：大预览框读的是已落库产物，不是现场生成。
- CRUD 的"改"里，全类型编辑成本高，先保证重命名+重新生成；讲义文本编辑可选做。
- 这两步把资源库从"演示级"升到"可部署运营的产品级"，答辩可讲"完整资源生命周期管理"。
