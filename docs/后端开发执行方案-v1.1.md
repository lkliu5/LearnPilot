# 智学中枢 · 后端开发执行方案 V1.1（B0–B8）

> 修订日期：2026-06-10（V1.0 → V1.1）
> 修订原因：《后端接口文档》基于前端真实代码逆向整理（30 接口 / 12 模块），覆盖**岗位市场、知识图谱、掌握度/旅程、多模态画像解析、苏格拉底对话**等 V1.0 方案未覆盖的模块。本版以接口文档为联调契约重排阶段。
> 性质不变：每阶段独立实施、单独交付、完成后实测验证。

---

## 〇、全局工程纪律

1. **契约权威顺序（V1.1 关键修订）**：`后端接口文档.md`（前端逆向，30 接口）> 前端 `src/` TypeScript 类型 > 《开发需求说明文档》5.1 节。需求文档的 4 个老接口与新接口的**映射对照表**写进 README，供评审核对「接口规范符合度」，不再按老契约实现。
2. **统一响应信封**：全局采用接口文档 1.2 的 `{code, message, data, traceId}`，FastAPI 中间件/装饰器统一包裹；错误码按 1.3（含 `2002` 离线降级）。WS/SSE 推送消息同样套此信封。
3. **Mock-first**：所有 LLM 调用经 `LLMClient` 适配层（mock / deepseek / qwen / anthropic 可配），Mock 模式按各接口契约返回结构化假数据，**无密钥可跑通全部 30 个接口**。
4. **轻量优先**：Chroma + SQLite + bge 本地模型 + 内存 TTL 会话；Milvus/PostgreSQL/Redis/Neo4j 作为生产替换路径写 README。
5. **每阶段 ≤ 8 个新文件**，完成即停，输出：文件清单 + 启动/验证命令 + curl/pytest 实测结果，0 报错才算完成。
6. **目录结构**：按需求文档 9.1 的 `backend/app/{api,agents,core,workflows,rag,services,models,schemas}`。
7. **异步任务**：统一 `taskId` 状态机（`pending→running→succeeded/failed`），`GET /tasks/{taskId}` 轮询 + `WS /ws/tasks/{taskId}` 可选推送（接口文档 1.4）。

## ②、阶段规划（V1.1 重排，对齐接口文档的 P0/P1/P2 联调优先级）

```
B0 骨架 ─► B1 数据+双角色认证 ─► B2 P0主流程API(Mock) ─► B3 RAG管道 ─► B4 管理端前端
                                                            │
                                  B5 LangGraph+真实生成 ◄────┘
                                  B6 P1特色API ─► B7 P2增强+WS ─► B8 测试交付
```

**核心策略变化**：V1.0 是「先建全部基建再接 API」；V1.1 改为「**B2 先用 Mock 数据源把 P0 主流程 14 个接口全部立起来**」——前端可以立刻把 mock 切到真实 HTTP，联调风险最早暴露；RAG/LangGraph 在 B3/B5 落地后只替换 service 层实现，接口签名不动。

## B0 — 骨架与打通（半天）｜同 V1.0

FastAPI 入口 + CORS + 统一响应信封中间件 + `/api/v1/health` + traceId 注入；`config.py`（pydantic-settings）；requirements.txt。前端 Vite 代理已就绪。
**验证**：curl health 返回信封格式 `{code:0,...}`；前端 fetch 通。

## B1 — 数据层 + 双角色认证（1 天）

- **模型（按接口文档数据字典对齐字段名）**：User（含 `role`）、KnowledgePoint（种子 6 核心 + 图谱 12 节点）、Lesson、Mastery（`Record<kpId,KPStatus>` 行存）、Journey（hasDiagnosed/hasGeneratedPath/targetJobName/matchPct）、ResourceCache、QuizQuestion、KnowledgeDocument、PromptTemplate、JobSnapshot。
- JWT 认证（接口 1/2/3：login/forgot/logout），种子账号 `admin/admin123`、`learner_001/123456`；`require_admin` 依赖；登录响应含 `role + hasDiagnosed + hasGeneratedPath`（旅程初始化）。
- 数据脱敏日志拦截器（需求文档 7.4）一并埋好。
**验证**：登录拿 token；learner 访问 admin 路由 403；journey 初始字段正确。

## B2 — P0 主流程 14 接口（Mock 数据源版）（1.5 天）★ V1.1 新增关键阶段

把接口文档 P0 + 支撑接口一次立起，数据源用 DB 种子 + MockLLM：

- **Profile**：`POST /profile/parse`（multipart，pypdf 抽简历文本 → MockLLM 输出固定 6 维 skills，**无材料时 source=manual 不编造**）、`POST /profile/narrative`（Mock 模板拼两段带 sourceId）、`POST /profile/diagnosis-complete`、`GET /profile/ability-portrait`。
- **LearningPath**：`GET /learning-path`（DB 种子 6 课 + milestones + summary 计算）、`POST /learning-path/generate`（异步 taskId，Mock 1.5s 完成）。
- **Mastery/Journey**：`GET /mastery`、`POST /mastery/{kpId}/check|pass`（幂等）、`GET /journey`（按接口文档规则推导 currentStep）。**后端成为权威数据源**，前端 Zustand 退化为缓存。
- **Resource/Quiz**：`GET /resource/knowledge-point/{kpId}`、`POST /resource/lecture`（Mock 返回 3 难度讲义 + 固定 sources + hallucinationRate）、`GET /quiz/{kpId}`、`POST /quiz/{kpId}/submit`（判分 ≥60 → 联动 mastery pass，返回 wrong[]）。
- 通用：`GET /tasks/{taskId}`。
**验证**：curl 走完整闭环：登录→parse→narrative→diagnosis-complete→generate path→lecture→quiz submit→mastery 变 passed→journey.currentStep 推进。前端切真实 API 后四页无回归。

## B3 — RAG 管道（1.5 天）｜原 B2，内容不变

chunker（标题感知+重叠，记 source_location）→ bge-small-zh embedding → Chroma → BM25+向量 RRF 混合检索 → bge-reranker（失败降级仅 RRF + 日志）。管理接口四件套（upload/documents/delete/search-test）。种子知识库灌库脚本。
**验证**：search-test「反向传播」返回 top5 + rerank 分数 + 来源；pytest 切片边界。

## B4 — 管理端前端（1 天）｜原 B3

登录角色分流（B1 已有 role）；侧边栏 admin 分组：**知识库管理**（列表/上传/删除/检索测试面板，复用 SourceTrace 视觉）、**Prompt 管理**（三 Agent 模板编辑+热更新）、**指标看板**（三 gauge，复用 CountUp）。沿用玻璃发光令牌，≤5 文件/批。
**验证**：admin 上传→列表刷新→检索测试出结果；learner 看不到入口；0 控制台错误。

## B5 — LangGraph 多智能体 + 真实生成替换（1.5 天）｜原 B4

诊断/生成/审核三 Agent + LangGraph 状态机 + 审核不过重试 ≤2 + 降级标记；prompt 走 PromptTemplate 热更新；全程记录 trace。**替换 B2 的 Mock service**：`/resource/lecture` 走「RAG 检索→生成 Agent→审核 Agent→真实 sources + hallucinationRate（按①-4 口径计算）」；`/profile/parse|narrative` 接真实 LLM 抽取与叙述。接口签名零改动。
**验证**：Mock 与真实双模式各跑一遍 lecture，契约一致；人为低分触发重试。

## B6 — P1 特色接口（1 天）

- **JobMarket**：`GET /job-market/hot`、`GET /job-market/{id}`（托管 preset JSON + JobSnapshot 表；数据源不可用 → `code 2002 + offline:true` 降级，对齐前端「离线快照」标记）。
- **KnowledgeGraph**：`GET /knowledge-graph`（12 节点 13 边静态结构，category 由 mastery 实时推导：passed→0 / learning→1 / 高 value 未开始→2 / 盲区→3）。
- **Reinforce**：`POST /reinforce`（错题 → 诊断薄弱点 → 生成 recap + 追加练习；Mock 与真实 Agent 双模式）。
- **External**：`GET /resource/external/{kpId}`（精选资源库表 + 相关度/可信度评分；生产接搜索 API 路径写注释）。
- **Dashboard**：`GET /dashboard/overview`（聚合 mastery/journey/radar/strong/weak，overall_score 按掌握度加权）。
**验证**：故意答错→reinforce 出强化卡；mastery 变化→graph category 联动变色；dashboard 数值与明细接口一致。

## B7 — P2 增强 + 实时通道（1 天）

- **Workflow**：`POST /workflow/execute` + `GET /workflow/{id}` 轮询 + `WS /ws/workflow/{id}` 推送（消息结构按接口文档 11.2，驱动 AgentStatusCard 指示灯）；**前端保留「演示/实时」开关**，断网兜底。
- **SocraticTutor**：`POST /resource/tutor/chat`，SSE 流式（按①-5 格式）；会话上下文内存 TTL。
- **Video**：`POST /resource/video` 先返回 `videoUrl:null + narration[]`（走前端 Remotion Player + TTS）；服务端渲染 mp4 作可选加分。
**验证**：触发工作流→大屏节点随 WS 实时点亮；tutor 流式逐 token 渲染；断开 WS 自动回退演示模式。

## B8 — 测试与交付（1 天）｜原 B7

pytest（Agent 通信 / RAG / 接口契约快照测试——30 接口响应结构逐一断言防字段漂移）；三量化指标脚本（幻觉率 <5% / 适配率 ≥85% / 覆盖率 ≥90%）输出报告并接指标看板；≥3 组差异化画像种子；README（一键启动 / Mock 切换 / 新老接口映射表 / 生产替换路径）。
