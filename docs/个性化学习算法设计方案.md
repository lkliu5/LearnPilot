# 智学中枢个性化学习算法设计方案

> 任务：TASK-005-A 个性化学习知识状态模型设计  
> 文档性质：算法与架构设计，不包含业务代码、Agent、Workflow、RAG 或 API 变更  
> 设计基线：提交 `a3f4183`，2026-07-23 现有工作区  
> 核心目标：建立可解释、可更新、可规划的用户知识状态模型，作为 Knowledge Adaptive Path（KAP，知识自适应路径）的算法基础

## 0. 设计边界与原则

本方案只定义目标模型、计算口径、更新规则和未来融合方式。当前阶段不新增数据表，不修改已有 `Mastery`、`StudentPortrait`、`KnowledgePoint`、`Journey`，不改变 30 个核心接口及其字段，不进入 Agent、LangGraph Workflow、RAG 或前端实现。

设计遵循以下原则：

1. **契约优先**：现有 API 继续把 `Mastery.status` 作为对外权威三态；本文提出的连续掌握概率、置信度、遗忘参数均是未来内部模型，不反向改写当前接口语义。
2. **能力靠证据**：知识能力由诊断微测、正式测验、费曼讲解和学习行为等证据更新；自述只作低置信冷启动，不能直接判定“已掌握”。
3. **能力与偏好解耦**：能力决定“学什么、先学什么”，偏好决定“用什么形式学”；认知风格、学习节奏不进入能力分。
4. **状态与过程解耦**：看过讲义、完成笔记代表学习投入，不等于掌握；正式通过仍由契约规定的测验链路触发。
5. **确定性优先**：核心更新与规划可在 Mock 模式下零网络运行；LLM 仅负责抽取、解释或叙述，不负责最终数值裁决。
6. **可解释与可回放**：每次知识状态变化必须能追溯到证据、权重、时间和规则版本。
7. **局部更新**：一次反馈只更新相关知识节点及受约束的邻接节点，不因单次行为重算或污染整份画像。

## 1. 当前学习画像分析

### 1.1 当前画像由三类数据共同构成

| 数据层 | 当前载体 | 已有信息 | 当前用途 |
|---|---|---|---|
| 异质学生画像 | `StudentPortrait.dimensions` | `knowledge_base`、`cognitive_style`、`error_preference`、`learning_goal`、`prior_experience`、`learning_pace`，含来源与置信度 | 诊断展示、路径目标与资源形式适配 |
| 知识点能力快照 | `Mastery` | `status`、`score`、`confidence`、`score_source` | 能力雷达、薄弱点排序、是否通过 |
| 学习过程与效果 | `QuizAttempt`、`LearningStepProgress`、`LearningNote`、学习评估聚合 | 测验得分与趋势、学习步骤完成、笔记和费曼等行为 | 学情概览与学习评价，尚未统一进入知识状态更新 |

当前画像的正确方向是三分类：

- **能力维**：客观测量，可量化；细粒度能力应落在具体知识节点，不应只保留一个全局 `knowledge_base`。
- **偏好维**：类型变量，如图像型、文字型、案例型、快速概览型、稳步细钻型，不存在“高分更好”。
- **主观维**：学习目标和先验经历，用自然语言与来源置信度表达。

### 1.2 当前已具备的算法基础

- 已有 78 点、7 板块知识体系，知识点含 `id/code/category/level/prerequisites/is_core`，可视为知识 DAG 的基础数据。
- 诊断微测和正式 quiz 已统一写入同一条 `Mastery` 能力记录，分别作为低置信基线与高置信结果。
- 路径规划已读取画像、per-KP 分数、掌握状态、岗位需求和知识先修关系，并按偏好重排资源形式。
- 画像/掌握度指纹变化可使路径缓存失效并触发重算，已经具备“状态变、路径变”的基础闭环。
- `QuizAttempt`、学习步骤、笔记、费曼反馈和学习评估已产生可复用行为信号。

### 1.3 当前模型的主要缺口

1. **快照多、证据链弱**：`Mastery` 保留最新分数，但无法完整回答“为什么从 42 变成 68、由哪些证据造成”。
2. **最后一次覆盖过强**：正式 quiz 直接覆盖既有分数，未综合历史表现、题目难度、重复尝试和趋势。
3. **未建模遗忘**：长时间未复习的 80 分与刚测出的 80 分当前等价。
4. **置信度未参与推理**：有 `confidence` 字段，但路径判断主要读取 `score`；“高分低置信”与“高分高置信”没有充分区分。
5. **过程证据未闭环**：费曼暴露的概念缺口、重复卡点、笔记和学习步骤尚未稳定转为知识状态证据。
6. **知识粒度受限**：6 个核心点有完整测评闭环，其余目录点主要用于浏览、路径细化与先修推断，不能假装拥有同等可信掌握度。
7. **更新与规划耦合粗**：画像指纹变化会重算路径，但还没有“保留已完成步骤、只替换受影响未完成段”的局部重规划模型。
8. **口径存在待治理项**：接口文档 7.3/9.1 规定测验 `score >= 60` 触发 `passed`，当前 `quiz.py` 使用 70。本文不修改任何一方；后续实施前须按契约权威顺序单独校准。KAP 可保留 70 作为“熟练/可略读”阈值，但不能把它混同为 API 的通过阈值。

## 2. 用户知识状态模型

### 2.1 双层用户模型

用户模型定义为：

```text
LearnerModel(u, t) = {
  Portrait(u, t),       # 目标、经历、偏好、全局约束
  KnowledgeState(u, t)  # 每个知识节点的认知状态
}
```

`Portrait` 回答“这个人想学什么、偏好怎么学”；`KnowledgeState` 回答“这个人在每个知识点上会多少、证据多可靠、多久未巩固”。二者关联但不混合打分。

### 2.2 单用户单知识节点状态

对用户 `u`、知识节点 `k`、时刻 `t`，定义：

```text
KS(u,k,t) = <p, c, b, s, f, n, source, lastEvidenceAt, updatedAt, version>
```

| 字段 | 范围 | 含义 |
|---|---:|---|
| `p` | [0,1] | 掌握概率，模型对“当前能稳定完成该节点目标”的估计 |
| `c` | [0,1] | 置信度，表示证据量、证据质量与一致性，不等于掌握度 |
| `b` | 枚举 | 派生掌握层级：unknown / exposed / learning / proficient / mastered / review_due |
| `s` | 正数 | 记忆稳定度或建议复习间隔参数，越大遗忘越慢 |
| `f` | [0,1] | 当前遗忘风险，由距最近有效证据的时间和稳定度推导 |
| `n` | 非负整数 | 有效证据数量 |
| `source` | 枚举 | 最近主导证据来源，如 diagnostic / quiz / feynman / practice / inferred |
| `lastEvidenceAt` | 时间 | 最近一次有效学习证据时间 |
| `updatedAt` | 时间 | 本状态最近计算时间 |
| `version` | 字符串 | 算法与参数版本，保证可回放 |

其中 `p` 与 `c` 必须同时使用。例如：

- `p=0.82,c=0.25`：可能掌握，但证据不足，应安排短测确认；
- `p=0.62,c=0.92`：稳定处于学习中，应补弱项而非反复诊断；
- `p=0.86,c=0.90,f=0.65`：历史掌握较好但已到复习期，应排检索练习。

### 2.3 状态层级派生

状态层级只用于内部决策，不替换现有 API 三态：

| 内部层级 | 建议条件 | 教学含义 |
|---|---|---|
| `unknown` | 无有效证据或 `c < 0.20` | 先测后教，禁止臆断为零基础 |
| `exposed` | 有浏览/学习过程证据，但无有效测评 | 已接触，不代表会做 |
| `learning` | `p < 0.70` 且已有测评证据 | 继续学习与针对性练习 |
| `proficient` | `p >= 0.70` 且 `c >= 0.55` | 可降低讲解冗余、进入迁移任务 |
| `mastered` | 正式通过且 `p >= 0.80,c >= 0.70` | 可后置或跳过，但保留复习检查 |
| `review_due` | 原 proficient/mastered 且遗忘风险超过阈值 | 插入短复习或检索练习 |

对外兼容映射建议：

```text
API passed         ← 只服从现有正式通过链路，不由内部 p 单独触发
API pending-check  ← learning 且已满足检查条件
API learning       ← exposed / learning
未出现记录          ← unknown
```

这样可避免“诊断题答对 = 课程已学完”或“看过视频 = 已掌握”。

### 2.4 冷启动

冷启动按证据等级处理：

1. 正式诊断微测：生成每个被测节点的低至中置信基线。
2. 简历/自然语言自述：只生成画像和低置信先验，不得直接产生 `mastered`。
3. 直接跳过：节点保持 `unknown`，而不是伪造 0 分；教学策略可按零基础安全起点开始。
4. 先修推断：若高置信掌握高阶节点，可提高其先修节点的先验，但必须标 `source=inferred`、限制置信度上限，不能触发正式 `passed`。

## 3. 知识节点表示

### 3.1 知识图结构

知识体系表示为有向无环图：

```text
G = (V, E)
V = {知识节点 k}
E = {(ki, kj) | ki 是 kj 的先修}
```

当前 `KnowledgePoint` 已覆盖身份、分类、层级和先修边；目标知识节点在内部算法视图中可扩展为：

```jsonc
{
  "id": "transformer",
  "code": "LLM-2",
  "name": "Transformer架构",
  "category": "LLM",
  "level": "进阶",
  "prerequisites": ["nn", "attention"],
  "isCore": true,
  "objectives": ["解释自注意力", "完成张量形状推导", "识别典型误区"],
  "conceptTags": ["self-attention", "position-encoding"],
  "estimatedMinutes": 120,
  "difficulty": 0.65,
  "assessmentRefs": ["quiz:transformer"],
  "misconceptionTags": ["把位置编码视为注意力权重"]
}
```

上述新增项是**算法视图设计**，不是本任务的数据表或 API 变更。

### 3.2 节点的三种边

后续 KAP 内部可区分：

- `prerequisite`：硬先修，必须满足拓扑约束；
- `supports`：软支撑，可提高学习效果但非必需；
- `similar/error-linked`：概念相似或共性易错，用于推荐对比练习，不参与拓扑排序。

当前只有 `prerequisites` 时，KAP 仅使用硬先修边，不能从知识名称相似度擅造依赖。

### 3.3 目标节点集与先修闭包

根据学习目标、岗位要求或用户选择得到目标集 `T`，候选集为：

```text
C = T ∪ PrerequisiteClosure(T)
```

候选集必须满足：

- 所有目标节点的必要先修均在集合中，或已被高置信掌握；
- 未被可靠测量的非核心节点状态为 unknown，不以核心节点均分替代；
- 裁剪时不得删除仍被保留目标依赖的硬先修节点；
- 6 个核心节点继续作为已验证主干，72 个目录点按证据覆盖度逐步升级，不能声称同等测评完备。

## 4. 掌握度计算

### 4.1 证据统一表示

所有可影响知识状态的输入先规范化为 `LearningEvidence`：

```jsonc
{
  "evidenceId": "ev_xxx",
  "userId": "u_xxx",
  "kpId": "transformer",
  "type": "quiz",
  "result": 0.75,
  "quality": 0.90,
  "difficulty": 0.65,
  "sourceRef": "quiz_attempt:123",
  "occurredAt": "2026-07-23T10:00:00+08:00",
  "metadata": {"attempt": 2, "total": 8}
}
```

`result` 表示归一化表现，`quality` 表示这条证据本身的可信程度。建议初始权重如下，最终须通过离线数据校准：

| 证据类型 | 基础权重 `w_type` | 能否单独触发对外 passed | 说明 |
|---|---:|---|---|
| 正式 quiz | 1.00 | 是，仍按接口契约 | 最主要能力证据 |
| 迁移/实操任务 | 0.90 | 否，除非未来另有批准契约 | 更能反映应用能力 |
| 费曼讲解评估 | 0.70 | 否 | 对概念理解与缺口敏感 |
| 诊断微测 | 0.55 | 否 | 冷启动、题量少，置信度受限 |
| 错题订正/检索练习 | 0.50 | 否 | 适合复习更新 |
| 学习步骤完成 | 0.15 | 否 | 只证明接触和投入 |
| 自述/简历 | 0.10 | 否 | 只作低置信先验 |

### 4.2 时间衰减后的先验

设上次状态为 `p_(t-1)`，距最近有效证据时间为 `Δt`，节点记忆稳定度为 `s`，先计算遗忘风险：

```text
f_t = 1 - exp(-Δt / s)
```

将掌握概率向中性先验 `p0` 回归，而不是直接衰减到 0：

```text
p_prior = p0 + (p_(t-1) - p0) * exp(-Δt / s)
c_prior = c_(t-1) * exp(-Δt / sc)
```

默认 `p0` 可取 0.5；对完全无证据节点保持 unknown，不把 0.5 展示成“掌握 50%”。`s` 与置信衰减尺度 `sc` 按后续数据校准。刚掌握节点可取较短初始间隔，连续成功检索后逐步提高 `s`。

### 4.3 单条证据更新

采用确定性、可解释的对数几率更新。令：

```text
L_prior = logit(clamp(p_prior, ε, 1-ε))
r_e     = 2 * result_e - 1                    # [-1,1]
w_e     = w_type * quality_e * difficultyFit_e
L_post  = L_prior + η * w_e * r_e
p_post  = sigmoid(L_post)
```

其中：

- `η` 为学习率；
- `difficultyFit` 防止简单题高分过度抬升、超纲难题低分过度惩罚；
- 同一次提交涉及多题时，先按知识标签聚合，不能把整张卷的总分平均写入无关节点；
- 多次短时间重复刷同题应使用重复惩罚 `repeatPenalty <= 1`，降低证据独立性假设带来的虚高。

置信度更新建议：

```text
c_post = 1 - (1 - c_prior) * exp(-λ * w_e)
```

当新证据与高置信历史明显冲突时，不应只提高置信度：应降低 `c_post`，标记 `conflict=true`，安排不同题型复测。

### 4.4 批量证据与稳定度更新

同一时段多条证据按发生时间顺序更新。对一次成功的延迟检索：

```text
s_new = min(s_max, s_old * (1 + α * quality * intervalFactor))
```

对失败检索：

```text
s_new = max(s_min, s_old * (1 - β * severity))
```

这使“隔一段时间仍会”比“刚学完马上答对”更能增加长期稳定度。

### 4.5 先修传播边界

状态传播必须保守：

- 高阶节点的高置信成功可以给先修节点增加少量推断证据，但推断置信度设上限，例如 `<=0.55`；
- 某节点失败不能直接判定所有先修都不会，只能提高相关先修的复测优先级；
- 先修节点未掌握时，可降低后继节点的“可学习性”，但不能直接修改后继节点掌握概率；
- 推断证据不得触发 API `passed`。

### 4.6 当前模型到目标模型的兼容映射

在未来实施前，可将现有记录解释为初始快照：

| 当前数据 | 目标状态初始化建议 |
|---|---|
| `score_source=quiz` | `p=score/100`，`c≈0.85`，主证据 quiz |
| `score_source=diagnostic` | `p=score/100`，`c` 沿用但设置上限，主证据 diagnostic |
| `source=manual` | 低权重先验，不能派生 mastered |
| `status=passed` 但无分数 | 保留 passed 契约事实，内部 `p/c` 标记为待校准，不伪造精确分数 |
| 无记录 | unknown，不等同于 0 分 |

## 5. 学习反馈更新机制

### 5.1 反馈闭环

```text
学习行为/测评
  → 规范化 LearningEvidence
  → 去重、校验归属与时间
  → 更新目标知识节点 KS
  → 评估先修/后继影响与遗忘风险
  → 生成状态差异 KnowledgeStateDelta
  → 判断继续学习、复测、复习或局部重规划
```

### 5.2 事件处理规则

| 反馈事件 | 更新对象 | 主要效果 | 禁止效果 |
|---|---|---|---|
| 诊断微测 | 对应被测 kp | 建立低置信初始 `p/c` | 不得置 passed |
| 正式 quiz | 对应题目标签 kp | 强更新 `p/c`，按契约更新三态 | 不把一张卷总分铺给全部节点 |
| 费曼讲解 | 当前 kp + 明确 gap 标签 | 正确解释加证据，明确误区减证据 | 不由 LLM 文案直接写分 |
| 错题订正 | 错题对应 kp | 更新误区标签，成功延迟复测后增强稳定度 | 当场看答案不视为掌握 |
| 学习步骤完成 | 当前 kp | `unknown→exposed` 或增加参与度证据 | 不提高到 mastered |
| 笔记/康奈尔总结 | 当前 kp | 作为弱过程证据；结构完整可提高复测优先度判断 | 不按字数直接加能力分 |
| 长时间无反馈 | 已有状态 kp | 增加遗忘风险，必要时转 review_due | 不撤销历史 passed 事实 |

### 5.3 幂等、乱序与冲突

- `evidenceId` 唯一，同一事件重复投递只处理一次。
- 事件按 `occurredAt` 计算；迟到事件允许重放该节点事件序列，不直接覆盖最新状态。
- 每个状态记录 `algorithmVersion` 和 `lastEvidenceId`，使离线复算结果可比对。
- 同一来源的撤销或纠错使用补偿事件，不物理删除历史证据。
- LLM 输出只能产生候选标签、gap 或解释；规则层完成验证和数值更新。

### 5.4 重规划触发器

以下情况产生 `ReplanSignal`，但不要求每次都重算整条路径：

- 当前路径节点从 learning 变为 mastered；
- 当前或下一节点高置信失败，且缺失必要先修；
- 某已掌握节点进入 review_due；
- 学习目标、岗位或时间预算改变；
- 偏好稳定变化，仅需重排资源形式时标记 `resource_only=true`；
- 新证据使 `|p_new-p_old|` 超过阈值，或置信度跨越关键阈值。

## 6. KAP 路径规划设计

### 6.1 定位及与 CPDP 的关系

KAP（Knowledge Adaptive Path）是以动态知识状态为核心的闭环路径规划框架：

```text
KAP = 知识状态估计 + 先修约束 + 目标/预算优化 + 反馈后局部重规划
```

现有 CPDP 强调“能力定内容与顺序、偏好定呈现形式”。二者不冲突：

- **KAP** 是上层闭环，定义状态如何随反馈变化、何时改路；
- **CPDP** 是 KAP 的路径打分与资源呈现策略，可作为 `PathPolicy` 的当前实现；
- KAP 不用 LLM 替代拓扑、阈值和数值计算。

### 6.2 输入与输出

输入：

```text
G(V,E)               知识 DAG
KS(u,*,t)            用户各节点知识状态
Goal                  学习目标/目标岗位
Preference            认知风格、学习节奏
Budget                可用时间、每日节奏、最大步骤数
CurrentPlan           当前路径及已完成步骤
Constraints           硬先修、资源可用性、完成标准
```

输出：

```text
LearningPlan = {
  orderedSteps,
  estimatedTime,
  recommendedResource,
  completionCriteria,
  reason,
  planVersion,
  basedOnStateVersion
}
```

### 6.3 候选节点效用

对候选节点 `k` 定义：

```text
gap(k)         = 1 - p(k)
uncertainty(k) = 1 - c(k)
goalRel(k)     ∈ [0,1]
jobDemand(k)   ∈ [0,1]
reviewNeed(k)  = f(k)
cost(k)        = estimatedMinutes(k) / budgetScale
```

节点效用：

```text
U(k) = wg*gap
     + wu*uncertainty*probeValue
     + wt*goalRel
     + wj*jobDemand
     + wr*reviewNeed
     - wc*cost
     - wp*prerequisiteRisk
```

解释：薄弱且目标相关的节点优先；高不确定节点可能优先安排短测，而不是直接安排长课；到复习期的已掌握节点可插入低成本检索练习；缺先修的高阶节点受惩罚或先补先修。

### 6.4 规划约束

1. **硬先修约束**：对任意硬边 `(ki,kj)`，若 `ki` 未高置信掌握，则 `ki` 必须先于 `kj`。
2. **预算约束**：总预计时长不超过预算；没有显式预算时沿用当前最多 12 步的产品约束。
3. **完成保护**：已完成步骤冻结，不因新状态改变而重排历史。
4. **连续性约束**：尽量保留当前进行中步骤，避免轻微分数波动造成路径抖动。
5. **探索约束**：对 unknown 节点优先使用低成本探测任务，防止把“未测”一律当“不会”。
6. **资源约束**：只推荐系统实际可提供的资源类型；偏好只改变优先顺序，不丢失必要测评。

### 6.5 规划流程

```text
1. 从目标/岗位得到目标节点集 T
2. 求 T 的必要先修闭包，移除已高置信掌握且无需复习的节点
3. 对 unknown 节点生成 probe（短测）候选，对薄弱节点生成 learn/practice 候选
4. 在 DAG 上按拓扑可行集合逐轮选择最高效用节点
5. 受时间预算和最大步数约束裁剪
6. 按偏好选择每步推荐资源形式，并指定完成标准
7. 输出节点级 reason，明确能力、证据、目标和先修依据
8. 状态更新后比较影响范围，只局部修订未完成后缀
```

### 6.6 局部重规划

设当前路径为：

```text
P = P_done + P_active + P_future
```

重规划只作用于 `P_future`：

- `P_done` 永久保留为学习历史；
- `P_active` 默认保留，除非发现硬先修缺失或用户主动改变目标；
- 计算受状态变化节点的后继闭包 `Affected`；
- 只对 `P_future ∩ Affected` 与新增候选重排；
- 通过最小编辑距离或“保留步骤奖励”抑制无意义抖动；
- 形成 `PlanRevision`，列出保留、插入、删除、后移及理由。

### 6.7 可解释输出模板

每一步的理由由确定性事实先生成，再允许 LLM 润色：

```text
安排“注意力机制”为第 2 步：
- 当前掌握概率 0.43，置信度 0.78，属于高置信薄弱点；
- 它是 Transformer 的硬先修；
- 与“大模型应用工程师”目标相关度高；
- 建议先用知识图解，再用 5 题短测完成检验。
```

LLM 不得改变节点顺序、数值、依赖和完成标准。

### 6.8 KAP 伪代码

```text
function KAP(user, goal, budget, currentPlan):
    states  = loadKnowledgeStates(user)
    graph   = loadKnowledgeGraph()
    targets = resolveTargets(goal)
    C       = prerequisiteClosure(targets, graph)

    tasks = []
    for k in C:
        state = applyTimeDecay(states[k])
        if state is unknown:
            tasks += ProbeTask(k)
        else if state is review_due:
            tasks += ReviewTask(k)
        else if not highConfidenceMastered(state):
            tasks += LearnTask(k)

    feasible = topologicalReadySet(tasks, graph, states)
    future = []
    while feasible not empty and cost(future) < budget:
        task = argmax Utility(task, states, goal, budget)
        future.append(task)
        feasible = updateReadySet(feasible, task, graph)

    future = stabilizeAgainstCurrentPlan(future, currentPlan.future)
    future = attachPreferredResources(future, user.preferences)
    return freeze(currentPlan.done) + preserve(currentPlan.active) + future
```

## 7. 与 Agent Workflow 融合方案

### 7.1 融合定位

本任务不修改现有 Agent 或 Workflow。未来融合时，知识状态模型应作为独立、确定性的领域能力，通过服务/工具被 Agent 调用，而不是把公式写进 Prompt。

建议职责边界：

| 组件 | 读取 | 产出 | 不应负责 |
|---|---|---|---|
| 学习诊断 Agent | 画像、微测、历史证据 | `DiagnosisResult`、待补信息 | 直接判 passed、自由修改状态分 |
| Knowledge State Engine | `LearningEvidence`、旧状态 | 新状态、状态差异、置信/遗忘风险 | 生成教学文案、调用 RAG |
| 知识规划 Agent | 状态快照、知识 DAG、目标、预算 | KAP 计划与规划理由 | 直接写测验结果、修改证据历史 |
| 资源生成 Agent | 当前计划步骤、适配摘要、证据包 | 个性化资源 | 修改画像、掌握度、路径顺序 |
| 教学交互 Agent | 当前步骤、资源、偏好 | 教学回合、结构化学习证据 | 以对话印象直接加分 |
| 质量评估 Agent | 资源、教学回合、学习证据 | 质量报告、gap、重规划建议 | 绕过状态引擎直接更新 Mastery |
| Workflow Controller | 结构化事件与状态差异 | 路由、重试、持久化、结束 | 解析自然语言决定数值状态 |

### 7.2 推荐状态对象

未来 `LearningContext` 可只带快照与引用，避免在 Agent 间复制整个历史：

```jsonc
{
  "stateVersion": "ks_v12",
  "portraitVersion": "v4",
  "planVersion": "plan_v7",
  "currentKpId": "transformer",
  "knowledgeStates": {
    "transformer": {"p": 0.43, "c": 0.78, "band": "learning", "forgettingRisk": 0.12}
  },
  "evidenceRefs": ["ev_101", "ev_102"]
}
```

Agent 消息只传 `evidenceRefs/stateVersion/planVersion` 等稳定引用；证据正文由受控工具按权限读取。

### 7.3 未来事件流

```text
教学交互/测验
  → LearningEvidence
  → Knowledge State Engine
  → KnowledgeStateDelta
      ├─ 无显著变化 → 继续当前步骤
      ├─ 达到完成条件 → 规划 Agent 选择下一步
      ├─ 发现先修缺口 → ReplanRequest
      ├─ 进入复习期 → 插入 ReviewTask
      └─ 证据冲突 → ContextRequest / ProbeTask
```

结构化消息建议沿用《Agent系统重构设计方案》的版本化协议：

- `learning.evidence.created`
- `knowledge_state.updated`
- `knowledge_state.conflict`
- `plan.revision.requested`
- `plan.revised`

这些是未来内部协议建议，不是当前 API 新增。

### 7.4 与现有资源生成 Workflow 的最小融合点

现有主流程为：

```text
diagnostic → retrieval → generation → validation → decision
```

未来最小侵入式融合可分三处：

1. `diagnostic` 前由上下文加载器读取 `KnowledgeStateSnapshot`，只读注入当前节点的 `p/c/b/f` 和偏好摘要；
2. `generation` 用状态层级决定讲解深度，用偏好决定首选形式；RAG 检索与可信审核保持原职责；
3. `decision` 只持久化资源产物，不更新知识状态；只有真实学习/测评事件才进入状态引擎。

路径规划仍可作为独立流程或未来 `plan_knowledge` 节点。资源质量失败触发资源修订，不应被误作学生能力下降。

### 7.5 一致性与安全要求

- Workflow 必须携带 `basedOnStateVersion`；写入时若状态版本已变化，重新评估而非覆盖新状态。
- 状态更新、证据入库、重规划信号应具备幂等键和 traceId。
- Agent 只能提交结构化候选证据；状态引擎校验 `userId/kpId/sourceRef` 后计算。
- 对外仍使用统一响应信封；本方案不改变任何现有 API。
- 日志中不记录原始隐私画像文本；手机号和邮箱继续由脱敏拦截器处理。
- Mock provider 必须能生成固定证据和确定性路径，保证无 API Key 全链路可测。

## 8. 参数、评估与后续实施建议

### 8.1 参数治理

`η/λ/α/β`、遗忘时间尺度、证据权重和各层级阈值必须集中版本化，禁止散落在 Agent Prompt 或多个服务中。初值只用于离线实验，不能宣称为经过教育数据验证的最优参数。

### 8.2 离线评估指标

后续进入实现阶段前，至少准备多用户、多节点、按时间排序的证据序列，评价：

- **预测准确性**：用前序状态预测下一次 quiz 是否通过，统计 AUC/Brier Score；
- **校准性**：预测掌握概率 0.7 的样本实际成功率是否接近 70%；
- **路径有效性**：单位学习时间的后测增益、目标节点达成率；
- **先修违规率**：未满足硬先修却安排高阶节点的比例，目标为 0；
- **路径稳定性**：无重大状态变化时的步骤编辑率；
- **冷启动诚实性**：未测节点被错误标为 mastered/passed 的比例，目标为 0；
- **可解释覆盖率**：每次状态变化与路径调整是否均有 evidenceRef 和规则版本。

### 8.3 建议实施顺序

若后续获准进入代码阶段，建议按独立任务推进，每次仍遵守阶段边界：

1. 先建立只读证据规范与离线状态计算器，不接生产 Workflow；
2. 用现有 `QuizAttempt` 回放校准掌握概率与置信度；
3. 增加影子计算，只对比现有 Mastery/路径，不影响线上结果；
4. 验证通过后再设计持久化与迁移；
5. 最后才接入 KAP 局部重规划和 Agent Workflow 事件协议。

## 9. 本阶段结论

智学中枢的个性化算法基础应从“画像字段 + 最新分数 + 静态三态”升级为“**画像约束 + 节点级概率状态 + 证据置信度 + 时间遗忘 + 反馈事件 + 局部重规划**”。

最终闭环为：

```text
画像定义目标与偏好
  → 知识状态判断会什么、证据是否可靠
  → KAP 在知识 DAG 上生成可执行路径
  → 教学与测评产生新证据
  → 状态引擎确定性更新
  → 仅对受影响的未来路径局部修订
```

该模型保留现有契约、Mock-first 能力和已实现 CPDP 机制，同时为后续学习诊断、资源适配、教学交互、质量评价与多智能体协作提供统一的算法状态基础。
