# 智学中枢文档中心

本目录是项目非代码资料的统一入口。继续开发前，先阅读本页和
[`维护/当前工程状态.md`](维护/当前工程状态.md)，不要从 `progress/` 或旧版 CC 指令反推当前实现。

## 文档优先级

发生冲突时按以下顺序裁决：

1. [`后端接口文档.md`](后端接口文档.md)：接口路径、字段名、枚举和错误码的唯一权威。
2. `frontend/src/` 中的 TypeScript 类型：前端实际消费契约。
3. [`开发需求说明文档.md`](开发需求说明文档.md)：业务目标、算法与总体架构。
4. [`维护/当前工程状态.md`](维护/当前工程状态.md)：当前完成度、真实/Mock 边界和下一步。
5. [`后端开发执行方案-v1.1.md`](后端开发执行方案-v1.1.md)：B0–B8 的历史实施依据，不代表当前阶段上限。
6. `progress/`、`归档/`：历史证据，不用于覆盖当前契约。

## 持续维护区

| 文档 | 用途 | 何时更新 |
|---|---|---|
| [`维护/当前工程状态.md`](维护/当前工程状态.md) | 接手入口、模块完成度、风险、下一步 | 每个开发阶段或重要功能完成后 |
| [`维护/文档维护规则.md`](维护/文档维护规则.md) | 文档生命周期、命名、归档规则 | 文档制度变化时 |
| [`后端接口文档.md`](后端接口文档.md) | API 契约 | 接口正式新增或契约批准变更时 |
| [`开发需求说明文档.md`](开发需求说明文档.md) | 产品需求和算法依据 | 需求正式变更时 |
| 根目录 `README.md` | 安装、启动、验证 | 命令、依赖或运行环境变化时 |
| 根目录 `AGENTS.md` | 开发纪律 | 团队协作规则变化时 |

持续维护文档必须描述“现在是什么”，不得堆叠逐日操作记录。

## 固化日志资产

以下内容是生产过程证据，完成后原则上不再修改：

- `progress/B*.md`、`progress/C*.md`：阶段验收记录。
- `progress/CC-*.md`、`progress/fix-*.md`、`progress/feat-*.md`：历史任务执行结果。
- `progress/联调-*.md`：当时的联调回包与验证结果。
- `归档/任务指令/`：已经执行完的 CC 工作指令。
- `归档/设计演进/`：旧版 UI、产品和 PPT 方案。
- 截图、指标报告、演示输出：对应版本的证据快照。

发现历史日志与当前代码不一致时，不修改历史结论；应更新“当前工程状态”，必要时新增一条新的进度记录。

## 交付物与大文件

PPT、DOCX、PDF、视频素材、截图和 ZIP 属于交付资产或构建资产。当前仍可能由 WPS、PPT 脚本或录屏流程使用，本轮不批量移动或删除。维护时遵循：

- 同类文件只指定一个“当前版”，旧版本移入归档。
- `~$*.docx`、`~$*.pptx`、`.wpp_backup/` 是编辑器临时文件，不作为项目资产。
- `.pptx-build/`、截图脚本输出和压缩包是可再生构建资产，不作为需求或实现依据。
- 证件、个人材料等敏感文件不得纳入源码仓库或交给自动化处理。

## 新成员接手顺序

1. 阅读根目录 `AGENTS.md`。
2. 阅读本页和“当前工程状态”。
3. 按任务需要阅读接口文档或需求文档的对应章节。
4. 查看最近一条相关 `progress/` 日志了解验证方式。
5. 以代码、测试和实际回包确认现状，不能只相信旧日志。
