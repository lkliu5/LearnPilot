# 智学中枢生产部署方案

## 1. 文档目的

本文用于将「智学中枢（软件杯）」部署到单台 Linux 服务器，适用于比赛演示、小规模试用和单机生产环境。

当前项目技术栈：

- 前端：React 18 + TypeScript + Vite
- 后端：FastAPI + LangGraph
- 数据库：SQLite
- 向量库：Chroma 嵌入式存储
- 模型：本地 bge / Mock / DeepSeek 等可配置 Provider
- 本地产物：TTS 缓存、Remotion 视频、Chroma 数据和 SQLite 数据库

本方案不修改现有接口、前端 Store 或路由，继续保留无 API Key 时的 Mock 全链路。

---

## 2. 推荐部署架构

```text
浏览器
  │
  │ HTTPS :443
  ▼
Nginx
  ├── /              → frontend/dist 静态文件
  └── /api/*         → FastAPI 127.0.0.1:8000
                              │
                              ├── SQLite
                              ├── Chroma
                              ├── 本地模型缓存
                              ├── TTS 缓存
                              └── 视频产物
```

### 2.1 部署边界

当前版本推荐部署为单机、单后端进程：

- SQLite 和 Chroma 均为本地嵌入式存储。
- 异步任务状态已持久化，但执行器仍是单机 `asyncio`。
- 部分会话状态使用进程内 TTL 存储。
- TTS、视频和模型缓存均写入本地磁盘。

因此暂不应配置多个 Uvicorn Worker，也不应部署多个后端副本共同读写同一数据目录。

## 3. 服务器要求

### 3.1 最低配置

- Linux：Ubuntu Server 或同类发行版
- CPU：4 核
- 内存：8 GB
- 磁盘：40 GB
- 公网域名：1 个
- 开放端口：22、80、443

### 3.2 推荐配置

如果启用本地 bge、reranker、TTS 或视频渲染，建议：

- CPU：8 核
- 内存：16 GB
- 磁盘：80 GB 以上
- 配置 Swap，避免模型首次加载时因内存峰值退出

### 3.3 软件依赖

- Python 3.11 或更高版本
- Node.js 与 npm
- Nginx
- Git
- SQLite 命令行工具（用于备份和维护）

如果启用服务端 MP4 渲染，还需要：

- `frontend/node_modules` 中的 Remotion Renderer
- 可用的无头 Chromium/Chrome
- 足够的临时磁盘和内存

资源有限时建议关闭服务端视频渲染，前端仍可使用现有降级播放能力。

## 4. 目录规划

推荐目录：

```text
/opt/zhixue/
├── app/                         # Git 项目代码
│   ├── backend/
│   └── frontend/
├── data/                        # 所有需要持久化的数据
│   ├── zhixue.db
│   ├── chroma/
│   ├── models/
│   ├── tts_cache/
│   └── video/
└── backups/                     # 数据库和数据目录备份
```

创建运行用户和目录：

```bash
sudo useradd --system --create-home --shell /bin/bash zhixue
sudo mkdir -p /opt/zhixue/app
sudo mkdir -p /opt/zhixue/data/chroma
sudo mkdir -p /opt/zhixue/data/models
sudo mkdir -p /opt/zhixue/data/tts_cache
sudo mkdir -p /opt/zhixue/data/video
sudo mkdir -p /opt/zhixue/backups
sudo chown -R zhixue:zhixue /opt/zhixue
```

将代码克隆或上传到：

```text
/opt/zhixue/app
```

## 5. 后端环境变量

进入后端目录：

```bash
cd /opt/zhixue/app/backend
cp .env.example .env
```

生产环境建议配置：

```env
APP_NAME=智学中枢后端
API_PREFIX=/api/v1

# 只允许正式前端域名跨域访问
CORS_ORIGINS=https://你的域名

# 生产日志
LOG_LEVEL=INFO
LOG_FORMAT=json
LOG_REQUEST_COMPLETED=true

# SQLite 绝对路径。sqlite://// 表示 Linux 绝对路径
DATABASE_URL=sqlite:////opt/zhixue/data/zhixue.db

# 持久化目录
CHROMA_DIR=/opt/zhixue/data/chroma
MODEL_CACHE_DIR=/opt/zhixue/data/models
TTS_CACHE_DIR=/opt/zhixue/data/tts_cache
VIDEO_RENDER_DIR=/opt/zhixue/data/video
VIDEO_FRONTEND_DIR=/opt/zhixue/app/frontend

# 必须替换默认值
JWT_SECRET=替换为独立高强度随机字符串
MODEL_KEY_SECRET=替换为另一个独立高强度随机字符串

# 无 Key 演示模式
LLM_PROVIDER=mock

# 使用 DeepSeek 时启用
# LLM_PROVIDER=deepseek
# DEEPSEEK_API_KEY=你的DeepSeek密钥
# DEEPSEEK_MODEL=deepseek-chat

# 外部资源搜索；无 Key 时使用缓存或种子降级
SEARCH_PROVIDER=none
# SEARCH_PROVIDER=tavily
# SEARCH_API_KEY=你的搜索密钥

# 服务器资源有限时关闭 MP4 渲染
VIDEO_RENDER_ENABLED=false

# TTS 无法访问外网时可关闭，前端继续使用降级能力
TTS_PROVIDER=edge
```

分别生成 `JWT_SECRET` 和 `MODEL_KEY_SECRET`：

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(64))"
python3 -c "import secrets; print(secrets.token_urlsafe(64))"
```

两个密钥必须不同，并应保存在服务器秘密管理系统或受限权限的 `.env` 文件中：

```bash
chmod 600 /opt/zhixue/app/backend/.env
```

## 6. 安装并验证后端

```bash
cd /opt/zhixue/app/backend

python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
# requirements-dev.txt 会同时引入 requirements.txt，并固定已验收的 pytest 版本
.venv/bin/pip install -r requirements-dev.txt
```

执行数据库迁移：

```bash
.venv/bin/python -m app.core.migrations current
.venv/bin/python -m app.core.migrations upgrade
```

执行自动化测试：

```bash
.venv/bin/python -m pytest -q
```

临时启动验证：

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

在另一个终端验证：

```bash
curl http://127.0.0.1:8000/api/v1/health
```

预期返回统一响应信封，且 `code=0`、`data.status=ok`。

## 7. 使用 systemd 托管后端

创建：

```text
/etc/systemd/system/zhixue-backend.service
```

内容：

```ini
[Unit]
Description=Zhixue FastAPI Backend
After=network.target

[Service]
Type=simple
User=zhixue
Group=zhixue
WorkingDirectory=/opt/zhixue/app/backend
EnvironmentFile=/opt/zhixue/app/backend/.env
ExecStart=/opt/zhixue/app/backend/.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=5
TimeoutStopSec=30

[Install]
WantedBy=multi-user.target
```

启用服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable zhixue-backend
sudo systemctl start zhixue-backend
sudo systemctl status zhixue-backend
```

查看日志：

```bash
sudo journalctl -u zhixue-backend -f
```

生产环境不要使用 `--reload`。当前阶段不要增加 `--workers`。

## 8. 构建前端

创建生产环境配置：

```bash
cd /opt/zhixue/app/frontend
cat > .env.production <<'EOF'
VITE_USE_REAL_API=true
EOF
```

安装锁定依赖并构建：

```bash
npm ci
npm run build:check
```

生产产物：

```text
/opt/zhixue/app/frontend/dist
```

前端 API 基地址为相对路径 `/api/v1`，部署为同域后不需要修改前端业务代码。

不要在生产环境使用 `npm run dev` 或 `vite preview` 对公网提供服务。

## 9. 配置 Nginx

创建：

```text
/etc/nginx/sites-available/zhixue
```

内容：

```nginx
server {
    listen 80;
    server_name 你的域名;

    root /opt/zhixue/app/frontend/dist;
    index index.html;

    # 文档上传的第一层限制；还应在后端增加业务级文件大小校验
    client_max_body_size 30m;

    # React SPA 路由回落
    location / {
        try_files $uri $uri/ /index.html;
    }

    # HTTP、SSE、WebSocket 共用 API 代理
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $http_connection;

        # SSE/长任务不缓存
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

启用站点：

```bash
sudo ln -s /etc/nginx/sites-available/zhixue /etc/nginx/sites-enabled/zhixue
sudo nginx -t
sudo systemctl reload nginx
```

检查：

```bash
curl http://你的域名/api/v1/health
```

## 10. HTTPS 与防火墙

生产环境必须启用 HTTPS。可使用 Certbot、云平台证书或已有证书系统。

配置原则：

- HTTP 80 自动跳转到 HTTPS 443。
- 前端、API、SSE 和 WebSocket 使用同一域名。
- `CORS_ORIGINS` 设置为正式 HTTPS 域名。
- FastAPI 的 8000 端口只监听 `127.0.0.1`，不能直接暴露公网。

防火墙仅开放：

```text
22/tcp   SSH
80/tcp   HTTP
443/tcp  HTTPS
```

## 11. 默认账号与安全加固

项目种子账号包含演示口令，上公网前必须修改：

- `admin / admin123`
- `learner_001 / 123456`

至少完成以下加固：

1. 修改或禁用所有演示账号。
2. 替换 `JWT_SECRET` 和 `MODEL_KEY_SECRET`。
3. `.env` 权限设置为 `600`，禁止进入 Git。
4. 不在日志中打印 API Key、完整手机号或邮箱。
5. Nginx 限制上传大小。
6. 后端补充单文件和批量上传的业务级大小限制。
7. 通过 HTTPS 提供登录和模型密钥配置页面。
8. 配置登录、生成接口和上传接口的限流策略。
9. 定期升级系统安全补丁和 Python/Node 依赖。

当前版本适合比赛演示和受控试用；在未补充上传限制、限流和安全审计前，不建议直接开放给不受信任的大规模公网用户。

## 12. 数据持久化与备份

必须持久化：

```text
/opt/zhixue/data/zhixue.db
/opt/zhixue/data/chroma/
/opt/zhixue/data/models/
/opt/zhixue/data/tts_cache/
/opt/zhixue/data/video/
```

### 12.1 SQLite 备份

SQLite 使用 WAL 模式，不建议在运行中只复制一个 `.db` 文件。

推荐使用 SQLite 在线备份：

```bash
mkdir -p /opt/zhixue/backups/$(date +%F)
sqlite3 /opt/zhixue/data/zhixue.db \
  ".backup '/opt/zhixue/backups/$(date +%F)/zhixue.db'"
```

也可以暂停服务后复制数据库及其 WAL/SHM 伴生文件：

```bash
sudo systemctl stop zhixue-backend
cp -a /opt/zhixue/data/zhixue.db* /opt/zhixue/backups/$(date +%F)/
sudo systemctl start zhixue-backend
```

### 12.2 Chroma 和媒体备份

为保证 Chroma 目录的一致性，建议在低峰维护窗口短暂停止后端后执行目录备份：

```bash
sudo systemctl stop zhixue-backend
rsync -a /opt/zhixue/data/chroma/ /opt/zhixue/backups/$(date +%F)/chroma/
rsync -a /opt/zhixue/data/video/ /opt/zhixue/backups/$(date +%F)/video/
sudo systemctl start zhixue-backend
```

模型和 TTS 缓存可以重新生成；磁盘紧张时可不纳入长期备份。

建议至少：

- 每日备份 SQLite。
- 每周备份 Chroma 和视频产物。
- 保留 7 个日备份和 4 个周备份。
- 定期执行恢复演练，确认备份不是损坏文件。

## 13. 发布更新流程

每次发布建议使用版本目录或 Git Commit 标记：

```bash
cd /opt/zhixue/app
git fetch --all
git checkout <已验证的commit或tag>
```

发布前备份：

```bash
sqlite3 /opt/zhixue/data/zhixue.db \
  ".backup '/opt/zhixue/backups/pre-release-$(date +%F-%H%M).db'"
```

更新后端：

```bash
cd /opt/zhixue/app/backend
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m app.core.migrations upgrade
.venv/bin/python -m pytest -q
sudo systemctl restart zhixue-backend
```

更新前端：

```bash
cd /opt/zhixue/app/frontend
npm ci
npm run build:check
sudo nginx -t
sudo systemctl reload nginx
```

发布后立即执行健康检查和核心业务冒烟测试。

## 14. 回滚方案

### 14.1 代码回滚

```bash
cd /opt/zhixue/app
git checkout <上一个稳定commit或tag>
```

重新安装依赖、构建前端并重启后端。

### 14.2 数据库回滚

数据库迁移回滚具有破坏性，只能在确认目标版本且已有备份时执行：

```bash
cd /opt/zhixue/app/backend
.venv/bin/python -m app.core.migrations current
.venv/bin/python -m app.core.migrations downgrade --target <目标版本>
```

优先恢复发布前数据库备份，而不是盲目执行降级。

### 14.3 前端回滚

重新检出上一个稳定版本并执行：

```bash
cd /opt/zhixue/app/frontend
npm ci
npm run build:check
sudo systemctl reload nginx
```

## 16. 常见故障排查

### 16.1 前端打开后仍显示 Mock 数据

检查构建前的环境变量：

```env
VITE_USE_REAL_API=true
```

修改后必须重新执行 `npm run build:check`。

### 16.2 API 返回 502

```bash
sudo systemctl status zhixue-backend
sudo journalctl -u zhixue-backend -n 200 --no-pager
curl http://127.0.0.1:8000/api/v1/health
```

### 16.3 WebSocket 或 SSE 不工作

检查 Nginx：

- `proxy_http_version 1.1`
- `Upgrade` / `Connection` 请求头
- `proxy_buffering off`
- 长连接超时时间

### 16.4 SQLite 无法写入

```bash
sudo chown -R zhixue:zhixue /opt/zhixue/data
sudo -u zhixue test -w /opt/zhixue/data
```

同时检查磁盘空间和 WAL 伴生文件权限。

### 16.5 Chroma 或模型加载失败

检查：

- `/opt/zhixue/data/chroma` 是否可写。
- `/opt/zhixue/data/models` 是否可写。
- 服务器是否可以下载模型。
- 内存是否充足。

模型加载失败时项目会按配置降级，但 RAG 质量可能下降。

### 16.6 视频渲染失败

如果比赛部署不要求预生成 MP4，设置：

```env
VIDEO_RENDER_ENABLED=false
```

系统会保留现有前端播放降级能力，不影响讲义、图解、练习等主链路。

## 17. 后续容器化建议

当前仓库尚未提供 Dockerfile、Docker Compose 和正式 Nginx 模板。

后续容器化时建议拆为：

```text
nginx/frontend 容器
fastapi/backend 容器（单副本）
持久化 volume：SQLite + Chroma + media + model cache
```

容器化阶段仍需保持后端单副本，除非未来完成以下改造：

- SQLite 替换为可并发数据库。
- Chroma 切换为可共享服务或独立向量数据库。
- 内存会话迁移到共享会话存储。
- 异步任务迁移到支持多实例竞争与重放的任务队列。
- 本地媒体迁移到对象存储。

在这些改造完成前，单机 systemd + Nginx 是当前项目最简单、稳定且与业务实现一致的部署方式。
