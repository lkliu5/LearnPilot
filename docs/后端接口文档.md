## 1. 总体约定

### 1.1 基础规范

| 项 | 约定 |
|---|---|
| **Base URL** | `/api/v1` |
| **协议** | HTTPS |
| **请求/响应体** | `application/json; charset=utf-8`（文件上传用 `multipart/form-data`） |
| **时间格式** | ISO 8601，带时区，如 `2026-06-06T06:10:00+08:00` |
| **字符编码** | UTF-8（含中文字段值，如知识点名称、维度名称） |
| **鉴权** | 除登录外，所有接口需 `Authorization: Bearer <token>` |

### 1.2 统一响应信封

所有接口统一返回如下结构（前端可解构 `data` 字段）：

```jsonc
{
  "code": 0,           // 0 = 成功；非 0 = 业务错误码
  "message": "ok",     // 错误时为可读提示
  "data": { /* 业务数据，见各接口 */ },
  "traceId": "a1b2c3"  // 链路追踪 ID，便于排查
}
```

### 1.3 错误码约定

| code | 含义 | HTTP Status |
|---|---|---|
| 0 | 成功 | 200 |
| 1001 | 参数校验失败 | 400 |
| 1002 | 未认证 / token 失效 | 401 |
| 1003 | 无权限 | 403 |
| 1004 | 资源不存在 | 404 |
| 2001 | LLM/Agent 生成失败 | 500 |
| 2002 | 上游数据源（岗位快照等）不可用，已降级 | 200（`data.offline=true`） |
| 5000 | 服务器内部错误 | 500 |

### 1.4 异步任务约定

资源生成、工作流执行等耗时操作采用 **「提交任务 → 轮询状态 / WebSocket 推送」** 模式：

- 提交后返回 `taskId`，状态机：`pending → running → succeeded / failed`
- 轮询：`GET /api/v1/tasks/{taskId}`
- 推送（可选）：`WS /api/v1/ws/tasks/{taskId}`

## 2. 数据模型字典

以下为跨模块复用的核心数据结构，**字段名与前端 TypeScript 类型严格对齐**。

### 2.1 KnowledgePoint（知识点）
> 来源：`frontend/src/data/knowledgePoints.ts`

```jsonc
{
  "id": "nn",              // 知识点 ID，与知识图谱节点 ID 复用
  "name": "神经网络基础",   // 显示名
  "lessonSeq": 2,          // 对应学习路径课程序号
  "graphNodeId": "nn"      // 对应知识图谱节点 ID
}
```

固定 6 个核心知识点：`ml`(机器学习基础)、`nn`(神经网络基础)、`dl`(深度学习原理)、`cnn`(CNN架构)、`transformer`(Transformer架构)、`finetune`(大模型微调技术)。

### 2.2 KPStatus（掌握状态枚举）
> 来源：`frontend/src/store/mastery.ts`

```
"learning"      // 学习中
"pending-check" // 待检验
"passed"        // 已通过
```

### 2.3 Lesson（学习路径课程）
> 来源：`frontend/src/data/learningPath.ts`

{
  "sequence": 3,                 // 课程顺序（1-6）

## 3. 认证模块 Auth
> 对应前端：`frontend/src/pages/Login.tsx`（当前为 1s setTimeout 模拟，任意账号可登录）

### 3.1 登录

`POST /api/v1/auth/login`

**请求体：**
```jsonc
{
  "username": "学习者_001",
  "password": "******",
  "remember": true        // 记住登录，可选
}
```

**响应 `data`：**
```jsonc
{
  "token": "eyJhbGci...",
  "expiresIn": 7200,
  "user": {
    "userId": "u_10001",
    "username": "学习者_001",
    "displayName": "学习者_001",
    "hasDiagnosed": false,         // 用于前端 Journey 状态初始化
    "hasGeneratedPath": false
  }
}
```

### 3.2 找回密码（占位）

`POST /api/v1/auth/forgot-password` · 请求 `{ "email": "x@x.com" }` · 响应 `{ "sent": true }`

### 3.3 退出登录

`POST /api/v1/auth/logout` · 无请求体 · 使当前 token 失效

## 4. 画像诊断模块 Profile
> 对应前端：`frontend/src/pages/ProfileBuilder.tsx`、`frontend/src/services/profileNarrative.ts`
> 当前 Mock：`mockParse()`（固定输出 ML:85/NN:72/DL:68/注意力:45/Transformer:30/微调:20）、`generateNarrative()`（前端模板合成）

### 4.1 多模态材料解析

将简历 / 截图 / 文本描述解析为结构化画像。

`POST /api/v1/profile/parse`
**Content-Type:** `multipart/form-data`

**表单字段：**
| 字段 | 类型 | 说明 |
|---|---|---|
| `files` | File[] | 简历(doc)、截图(image)，可多份；可为空 |
| `description` | string | 自由文本背景描述，可为空 |

**响应 `data`（ParsedProfile）：**
```jsonc
{
  "education": { "value": "硕士", "source": "resume" },   // source: resume|ocr|text|manual
  "major":     { "value": "人工智能", "source": "resume" },
  "goal":      { "value": "职业培训", "source": "text" },
  "skills": [
    { "name": "机器学习基础", "level": 85, "source": "resume" }
    // name 取自固定 6 维；level 0-100
  ],
  "materials": [
    { "id": "m1", "label": "我的简历.pdf", "kind": "doc" }  // kind: doc|image|text
  ]
}
```

> **业务约束（防幻觉）：** 若无任何材料上传（`files` 与 `description` 均空），`skills` 仍可给出但 `source` 必须为 `manual`，且不得编造工作经历——与前端 `generateNarrative` 在无材料时返回 null 的逻辑一致。

枚举参考（前端下拉项）：
- 学历 `education`：`本科 | 硕士 | 博士 | 其他`
- 专业 `major`：`计算机科学 | 电子信息 | 人工智能 | 软件工程 | 数据科学 | 其他`
- 目标 `goal`：`职业培训 | 技能认证 | 学术研究 | 兴趣学习 | 其他`

### 4.2 画像叙述生成（接地版 AI 总结）

基于结构化画像 + 材料引用，生成带**来源标注**的两段式叙述。

`POST /api/v1/profile/narrative`

**请求体：**
```jsonc
{
  "draft": { /* 4.1 的 ParsedProfile（education/major/goal/skills） */ },
  "materials": [ { "id": "m1", "label": "我的简历.pdf", "kind": "doc" } ],
  "targetJob": {                        // 可为 null
    "name": "大模型应用工程师",
    "radar": { "机器学习基础": 70, "...": 0 }
  }
}
```

**响应 `data`（Narrative）：**
```jsonc
{
  "paragraphs": [          // 恰好两段；每段是 NarrativeSegment 数组
    [
      { "text": "该学习者具备 ", "sourceId": null },
      { "text": "人工智能", "tone": "key", "sourceId": "m1" },   // tone: key(蓝,关键) | weak(暖,薄弱)
      { "text": " 专业背景。" }
    ],
    [
      { "text": "与目标岗位相比，", "sourceId": null },
      { "text": "Transformer 能力偏弱", "tone": "weak" }
    ]
  ],
  "sources": [ { "id": "m1", "label": "我的简历.pdf", "kind": "doc" } ],
  "materialCount": 1
}
```

### 4.3 完成诊断（写入旅程状态）

`POST /api/v1/profile/diagnosis-complete`

**请求体：**
```jsonc
{
  "targetJobName": "大模型应用工程师",
  "matchPct": 62                 // 与目标岗位对标百分比 0-100
}
```

**响应 `data`：** `{ "hasDiagnosed": true }`
> 对应前端 `useJourney().completeDiagnosis({ targetJobName, matchPct })`，首页对标摘要条会回显。

### 4.4 能力画像（雷达数据）

供 Dashboard / 对标雷达图使用。

`GET /api/v1/profile/ability-portrait`

**响应 `data`：**
```jsonc
{
  "dimensions": ["机器学习基础","神经网络","深度学习","注意力机制","Transformer","大模型微调"],
  "values": [85, 72, 68, 45, 30, 20]
}
```

## 7. 掌握度与学习旅程 Mastery & Journey
> 对应前端：`frontend/src/store/mastery.ts`（localStorage `zx-mastery`）、`frontend/src/store/journey.ts`（localStorage `zx-progress`）
> 后端应作为权威数据源，前端 Store 退化为缓存。

### 7.1 获取掌握度全集

`GET /api/v1/mastery`

**响应 `data`：**
```jsonc
{
  "status": {                  // Record<knowledgePointId, KPStatus>
    "ml": "passed",
    "nn": "learning",
    "dl": "learning"
    // 未出现的知识点视为未开始
  }
}
```

### 7.2 标记知识点「去检验」

`POST /api/v1/mastery/{kpId}/check` → 将 `learning` 置为 `pending-check`（已 `passed` 保持不变）
**响应：** `{ "id": "nn", "status": "pending-check" }`

### 7.3 标记知识点「已通过」

`POST /api/v1/mastery/{kpId}/pass`（幂等）→ 置为 `passed`
**响应：** `{ "id": "nn", "status": "passed" }`
> 通常由测验通过（≥60 分）触发，见 9.1。

### 7.4 获取学习旅程状态

`GET /api/v1/journey`

**响应 `data`（JourneyState 子集）：**
```jsonc
{
  "hasDiagnosed": true,
  "hasGeneratedPath": false,
  "targetJobName": "大模型应用工程师",
  "matchPct": 62,
  "currentStep": "generate-path"   // diagnose|generate-path|learn|review（后端按规则推导）
}
```

> 旅程步骤推导规则（与前端 `getJourneyStep` 一致）：
> 未诊断 → `diagnose`；已诊断未生成路径 → `generate-path`；学习中 → `learn`；全部课程完成 → `review`。

## 8. 学习资源模块 Resource
> 对应前端：`frontend/src/pages/LearningResource.tsx` 及其子组件
> 当前 Mock：`lectureByLevel`（3 难度讲义）、`mindmapMarkdown`、`mermaidChart`、RAG 引用数固定 12、幻觉率固定 `<5%`

资源按知识点 + 难度生成，含 7 个 Tab：讲义 / 视频 / 思维导图 / 图表 / 代码 / 测验 / 外部资源 / 苏格拉底辅导。

### 8.1 获取知识点元信息

`GET /api/v1/resource/knowledge-point/{kpId}`
**响应 `data`：** `{ "id": "nn", "name": "神经网络基础", "description": "…", "status": "learning" }`

### 8.2 生成自适应讲义（核心）

`POST /api/v1/resource/lecture`

**请求体：**
```jsonc
{
  "kpId": "nn",
  "difficulty": "初级"      // 入门|初级|高级（注意资源页难度档与路径难度档不同）
}
```

**响应 `data`：**
```jsonc
{
  "kpId": "nn",
  "difficulty": "初级",
  "markdown": "# 神经网络基础\n\n## 1. 神经元模型 …(含 ```python 代码块```)",
  "sources": [                       // 供 SourceTrace 组件展示（RAG 引用）
    { "title": "《深度学习》花书 第6章", "type": "教材", "confidence": 0.92 }
  ],
  "hallucinationRate": 0.021         // 防幻觉校验结果，前端显示 <5%
}
```
> `sources[].type` 取值：`教材 | 论文 | 文档 | 课程`；`confidence` 0-1。前端切换难度时会触发本接口重新生成（当前模拟 1100ms）。

### 8.3 生成视频讲解

`POST /api/v1/resource/video` · 请求 `{ "kpId": "nn", "difficulty": "初级" }`

**响应 `data`：**
```jsonc
{
  "videoUrl": "https://.../nn.mp4",   // 服务端 Remotion 渲染产物；无则返回 null 走前端 Player
  "narration": [                      // 帧-旁白同步映射，供 TTS
    { "frame": 0, "text": "本节我们学习神经网络的基本结构…" }
  ],
  "fps": 30, "width": 1920, "height": 1080, "durationInFrames": 900
}
```

### 8.4 生成思维导图

`GET /api/v1/resource/mindmap/{kpId}`
**响应 `data`：** `{ "markdown": "# 神经网络\n## 前向传播\n## 反向传播\n…" }`（Markmap 语法）

### 8.5 生成 Mermaid 图表

`GET /api/v1/resource/diagram/{kpId}`
**响应 `data`：** `{ "mermaid": "graph TD; A[输入]-->B[加权求和]-->C[激活]…" }`

### 8.6 外部资源聚合

> 对应组件：`ResourceAggregator.tsx`（资源聚合 Agent 检索 + 审核 Agent 评分）

`GET /api/v1/resource/external/{kpId}`

**响应 `data`（ExternalResource[]）：**
```jsonc
[
  {
    "id": "r1",
    "type": "视频",                  // 视频|论文|文档|课程
    "title": "3Blue1Brown 神经网络系列",
    "source": "YouTube",
    "url": "https://…",
    "embed": "https://…/embed",      // 可嵌入播放地址，可选
    "duration": "19:13",             // 可选
    "relevance": 95,                 // 相关度 0-100（审核 Agent 评分）
    "credibility": 90,               // 可信度 0-100
    "reason": "权威科普，可视化讲解前向传播"
  }

## 14. 管理端模块 Admin

### 14.4 检索测试

```jsonc
{
  "rerankerUsed": true,            // false 表示 reranker 不可用，已降级为仅 RRF（见下方备注）

    {
      "chunkId": "doc_001#12",
      "documentId": "doc_001",

      "content": "反向传播通过链式法则将损失对各层参数求偏导……",

## 15. V1.1 接口增补说明

> 本章为对**既有接口的字段 / 语义增补**，原接口（第 3–12 章）定义逐字不变；以下新增字段、响应结构与流式格式以本章为准，联调时叠加生效。

### 15.1 登录响应增补 `role` 字段（缺口 #1）

[3.1 登录](#31-登录) 响应的 `user` 对象**新增** `role` 字段，前端据此做角色分流（learner 进学习者工作台，admin 进管理端）：

```jsonc
{
  "user": {
    "userId": "u_10001",
    "username": "学习者_001",
    "displayName": "学习者_001",
    "role": "learner",             // 新增：learner | admin
    "hasDiagnosed": false,
    "hasGeneratedPath": false
  }
}
```
> 种子账号：`admin / admin123`（`role=admin`）、`learner_001 / 123456`（`role=learner`）。第 14 章 `/admin/*` 接口的 `require_admin` 依赖即校验此字段。原 `user` 其余字段及登录请求体不变。

### 15.2 异步任务响应结构（缺口 #3）

补全 [30. `GET /tasks/{taskId}`](#13-附录接口总览表) 的响应结构（原仅定义路径与状态机）：

`GET /api/v1/tasks/{taskId}`

**响应 `data`：**
```jsonc
{
  "taskId": "t_abc",
  "status": "running",             // pending | running | succeeded | failed
  "progress": 60,                  // 0-100，可选；不支持细粒度进度时省略
  "result": null,                  // status=succeeded 时为任务产物（结构随任务类型而定，见下）
  "error": null                    // status=failed 时为 { "code": 2001, "message": "生成失败原因" }
}
```
> `result` 形态按任务来源：`/learning-path/generate` → `{ "lessons": [...] }`；`/admin/kb/upload` → `{ "documents": [{ "id","status":"indexed","chunks": 42 }] }`。`WS /api/v1/ws/tasks/{taskId}` 推送同结构信封，状态变化即推。

### 15.3 幻觉率（hallucinationRate）计算口径（缺口 #4）

[8.2 讲义](#82-生成自适应讲义核心) 与 [14.6 指标](#146-系统指标看板) 的 `hallucinationRate` 统一口径：

> **逐句接地校验**——将生成内容按句切分，每句与本次 RAG 检索命中的来源切片做 embedding 相似度比对，取最大相似度。低于阈值（默认 `0.75`）的句子视为「未接地（疑似幻觉）」。
>
> ```
> hallucinationRate = 未接地句数 / 总句数
> ```
>
> 取值 0-1，前端在 `< 0.05` 时显示「幻觉率 <5%」绿色标记。阈值可在配置中调整；无任何 RAG 来源（纯模板/兜底）时该值按约定置 `0` 并标注来源为模板，不参与质量统计。

### 15.4 苏格拉底辅导 SSE 流式格式（缺口 #5）

[8.7 苏格拉底辅导](#87-苏格拉底辅导对话式) 在请求头携带 `Accept: text/event-stream` 时切换为 SSE 流式输出，前端按 chunk 增量渲染；不带该头时仍返回 8.7 的整体 JSON（向后兼容）。

**`POST /api/v1/resource/tutor/chat`**（`Accept: text/event-stream`）

**流式响应（`Content-Type: text/event-stream`）：**
```
data: {"delta":"好"}

data: {"delta":"问题"}

data: {"delta":"。先想一想："}

event: done
data: {"sessionId":"s_123","suggestions":["等价于线性变换","可以拟合任意函数","不确定"]}

```
> 约定：
> - 增量 token 以默认事件 `data: {"delta":"<片段>"}` 逐条下发（每条以空行 `\n\n` 分隔）。
> - 流结束发送 `event: done`，其 `data` 携带最终 `sessionId` 与 `suggestions`（对应 8.7 JSON 的同名字段）。
> - 出错时发送 `event: error`，`data: {"code":2001,"message":"..."}`，前端回退提示并保留已渲染片段。
> - 会话上下文按 `sessionId` 在后端内存中按 TTL 维持。

### 15.5 岗位市场数据管线（缺口 #6）

[第 5 章 岗位市场](#5-岗位市场模块-job-market) 的数据来源在不同阶段的落地约定（接口签名不变）：

> - **Demo / 联调阶段（当前）：** 后端直接托管预置岗位 JSON（`PRESET`）+ `JobSnapshot` 快照表；`GET /job-market/hot` 与 `/job-market/{id}` 直接读取，`fetchedAt` 取快照入库时间。

> - **降级：** 实时数据源不可用时沿用 [5.2 降级约定](#52-岗位市场快照)——返回最近快照并置 `code 2002 / data.offline=true`，前端显示「离线快照」标记。

## 16. 账号体系增补（B9 可选增强）

> 本章为 B9 阶段新增的**账号注册与管理端用户管理**接口，沿用 1.2 统一信封与 1.3 错误码。
> 第 3 章登录与第 14 章管理端鉴权约束（`require_admin`，非管理员 → `1003`）对本章同样适用。
> 注：V1.1 字段补丁见第 15 章；本章为**新增接口**，故另起一章（15 章已被占用）。

### 16.0 登录（3.1）行为增补

[3.1 登录](#31-登录) 在 B9 增加两条语义（请求体与响应结构不变）：

> - **禁用拦截：** 账号被管理员禁用（`isActive=false`）时，登录返回 `code 1002 / HTTP 401`，`message="账号已禁用"`，不签发 token。
> - **活跃时间：** 登录成功刷新该用户 `lastActiveAt`（供 [16.2](#162-管理端用户列表) 列表展示「最近活跃」）。

### 16.1 注册

`POST /api/v1/auth/register`

**请求体：**
```jsonc
{
  "username": "新学习者",      // 必填，全局唯一
  "password": "******"        // 必填，长度 ≥ 6
}
```

**响应 `data`（与 [3.1 登录](#31-登录) 完全一致，注册成功即自动登录）：**
```jsonc
{
  "token": "eyJhbGci...",
  "expiresIn": 7200,
  "user": {
    "userId": "u_ab12cd34ef56",
    "username": "新学习者",
    "displayName": "新学习者",
    "role": "learner",          // 注册账号固定 learner
    "hasDiagnosed": false,      // 初始化未诊断旅程
    "hasGeneratedPath": false
  }
}
```
> 注册副作用：默认 `role=learner`、`isActive=true`；初始化 `Journey`（未诊断、未生成路径）、`Mastery` 为空集。
> **错误：** 用户名已存在 → `code 1001 / HTTP 400`，`message="用户名已存在"`；密码长度 < 6 → `code 1001 / HTTP 400`，`message="密码长度至少为 6 位"`。

### 16.2 管理端用户列表

`GET /api/v1/admin/users` · `require_admin`

**查询参数：** `page`（默认 1）、`pageSize`（默认 20，上限 100）

**响应 `data`：**
```jsonc
{
  "items": [
    {
      "userId": "u_10001",
      "username": "learner_001",
      "role": "learner",            // learner | admin
      "isActive": true,             // false 表示已被禁用，登录受阻（16.0）
      "hasDiagnosed": false,        // 旅程是否已完成画像诊断
      "passedKpCount": 0,           // 已通过（status=passed）的知识点数
      "createdAt": "2026-06-12T10:00:00+08:00",
      "lastActiveAt": null          // 最近一次登录时间；从未登录为 null
    }
  ],
  "total": 5,
  "page": 1,
  "pageSize": 20
}
```
> 列表按 `createdAt` 升序（种子账号在前），分页稳定。

### 16.3 重置学习进度

清空指定用户的 `Mastery` 与 `Journey`，回到未诊断初始态（幂等）。

`POST /api/v1/admin/users/{userId}/reset-progress` · `require_admin`

**响应 `data`：**
```jsonc
{
  "userId": "u_10001",
  "hasDiagnosed": false,          // 复位后恒为 false
  "masteryCleared": 3             // 本次清除的掌握度行数（幂等：再次调用为 0）
}
```
> **约束：** 目标用户不存在 → `code 1004 / HTTP 404`；目标 `role=admin` → `code 1003 / HTTP 403`，`message="不允许对管理员账号执行该操作"`（管理员无学习进度，禁止误操作）。

### 16.4 启用 / 禁用账号

翻转指定用户的 `isActive`（禁用后该账号登录被 16.0 拦截）。

`POST /api/v1/admin/users/{userId}/toggle-active` · `require_admin`

**响应 `data`：**
```jsonc
{
  "userId": "u_10001",
  "isActive": false               // 翻转后的最新状态
}
```
> **约束：** 目标用户不存在 → `code 1004 / HTTP 404`；目标 `role=admin` → `code 1003 / HTTP 403`，`message="不允许对管理员账号执行该操作"`（防止管理员自锁）。
