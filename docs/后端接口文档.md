## 1. 总体约定

### 1.1 基础规范

| 项 | 约定 |
|---|---|
| **Base URL** | `/api/v1` |
| **协议** | HTTPS |
| **请求/响应体** | `application/json; charset=utf-8`（文件上传用 `multipart/form-data`） |
| **时间格式** | ISO 8601，带时区，如 `2026-06-06T06:10:00+08:00` |
| **字符编码** | UTF-8（含中文字段值，如知识点名称、维度名称） |
| **鉴权** | 除登录外，所有接口需 `Authorization: Bearer <token>` |

### 1.2 统一响应信封

所有接口统一返回如下结构（前端可解构 `data` 字段）：

```jsonc
{
  "code": 0,           // 0 = 成功；非 0 = 业务错误码
  "message": "ok",     // 错误时为可读提示
  "data": { /* 业务数据，见各接口 */ },
  "traceId": "a1b2c3"  // 链路追踪 ID，便于排查
}
```

### 1.3 错误码约定

| code | 含义 | HTTP Status |
|---|---|---|
| 0 | 成功 | 200 |
| 1001 | 参数校验失败 | 400 |
| 1002 | 未认证 / token 失效 | 401 |
| 1003 | 无权限 | 403 |
| 1004 | 资源不存在 | 404 |
| 2001 | LLM/Agent 生成失败 | 500 |
| 2002 | 上游数据源（岗位快照等）不可用，已降级 | 200（`data.offline=true`） |
| 5000 | 服务器内部错误 | 500 |

### 1.4 异步任务约定

资源生成、工作流执行等耗时操作采用 **「提交任务 → 轮询状态 / WebSocket 推送」** 模式：

- 提交后返回 `taskId`，状态机：`pending → running → succeeded / failed`
- 轮询：`GET /api/v1/tasks/{taskId}`
- 推送（可选）：`WS /api/v1/ws/tasks/{taskId}`

## 3. 认证模块 Auth
> 对应前端：`frontend/src/pages/Login.tsx`（当前为 1s setTimeout 模拟，任意账号可登录）

### 3.1 登录

`POST /api/v1/auth/login`

**请求体：**
```jsonc
{
  "username": "学习者_001",
  "password": "******",
  "remember": true        // 记住登录，可选
}
```

**响应 `data`：**
```jsonc
{
  "token": "eyJhbGci...",
  "expiresIn": 7200,
  "user": {
    "userId": "u_10001",
    "username": "学习者_001",
    "displayName": "学习者_001",
    "hasDiagnosed": false,         // 用于前端 Journey 状态初始化
    "hasGeneratedPath": false
  }
}
```

### 3.2 找回密码（占位）

`POST /api/v1/auth/forgot-password` · 请求 `{ "email": "x@x.com" }` · 响应 `{ "sent": true }`

### 3.3 退出登录

`POST /api/v1/auth/logout` · 无请求体 · 使当前 token 失效

### 3.4 修改密码

`POST /api/v1/auth/change-password` · **需登录态**（请求头携带 `Authorization: Bearer <token>`）

校验旧密码后更新口令哈希（复用第 16 章账号体系的用户表与 `pbkdf2_sha256` 哈希逻辑，沿用 1.2 统一信封与 1.3 错误码）。

**请求体：**
```jsonc
{
  "oldPassword": "******",   // 必填，当前口令
  "newPassword": "******"    // 必填，新口令，长度 ≥ 6
}
```

**响应 `data`：**
```jsonc
{
  "userId": "u_ab12cd34ef56",
  "changed": true
}
```
> **鉴权：** 未携带 / 失效 token → `code 1002 / HTTP 401`（同 [3.3](#33-退出登录) 之 `get_current_user` 约束）。
> **错误：** 旧密码不正确 → `code 1001 / HTTP 400`，`message="旧密码错误"`；新密码长度 < 6 → `code 1001 / HTTP 400`，`message="密码长度至少为 6 位"`（与 [16.1 注册](#161-注册) 同口径）。
> 修改成功后旧 token 仍有效（不强制下线，前端可自行重登）；旧口令立即失效，新口令即时可用于 [3.1 登录](#31-登录)。

## 4. 画像诊断模块 Profile
> 对应前端：`frontend/src/pages/ProfileBuilder.tsx`、`frontend/src/services/profileNarrative.ts`
> 当前 Mock：`mockParse()`（固定输出 ML:85/NN:72/DL:68/注意力:45/Transformer:30/微调:20）、`generateNarrative()`（前端模板合成）

### 4.1 多模态材料解析

将简历 / 截图 / 文本描述解析为结构化画像。

`POST /api/v1/profile/parse`
**Content-Type:** `multipart/form-data`

**表单字段：**
| 字段 | 类型 | 说明 |
|---|---|---|
| `files` | File[] | 简历(doc)、截图(image)，可多份；可为空 |
| `description` | string | 自由文本背景描述，可为空 |

**响应 `data`（ParsedProfile）：**
```jsonc
{
  "education": { "value": "硕士", "source": "resume" },   // source: resume|ocr|text|manual
  "major":     { "value": "人工智能", "source": "resume" },
  "goal":      { "value": "职业培训", "source": "text" },
  "skills": [
    { "name": "机器学习基础", "level": 85, "source": "resume" }
    // name 取自固定 6 维；level 0-100
  ],
  "materials": [
    { "id": "m1", "label": "我的简历.pdf", "kind": "doc" }  // kind: doc|image|text
  ]
}
```

> **业务约束（防幻觉）：** 若无任何材料上传（`files` 与 `description` 均空），`skills` 仍可给出但 `source` 必须为 `manual`，且不得编造工作经历——与前端 `generateNarrative` 在无材料时返回 null 的逻辑一致。

枚举参考（前端下拉项）：
- 学历 `education`：`本科 | 硕士 | 博士 | 其他`
- 专业 `major`：`计算机科学 | 电子信息 | 人工智能 | 软件工程 | 数据科学 | 其他`
- 目标 `goal`：`职业培训 | 技能认证 | 学术研究 | 兴趣学习 | 其他`

### 4.2 画像叙述生成（接地版 AI 总结）

基于结构化画像 + 材料引用，生成带**来源标注**的两段式叙述。

`POST /api/v1/profile/narrative`

**请求体：**
```jsonc
{
  "draft": { /* 4.1 的 ParsedProfile（education/major/goal/skills） */ },
  "materials": [ { "id": "m1", "label": "我的简历.pdf", "kind": "doc" } ],
  "targetJob": {                        // 可为 null
    "name": "大模型应用工程师",
    "radar": { "机器学习基础": 70, "...": 0 }
  }
}
```

**响应 `data`（Narrative）：**
```jsonc
{
  "paragraphs": [          // 恰好两段；每段是 NarrativeSegment 数组
    [
      { "text": "该学习者具备 ", "sourceId": null },
      { "text": "人工智能", "tone": "key", "sourceId": "m1" },   // tone: key(蓝,关键) | weak(暖,薄弱)
      { "text": " 专业背景。" }
    ],
    [
      { "text": "与目标岗位相比，", "sourceId": null },
      { "text": "Transformer 能力偏弱", "tone": "weak" }
    ]
  ],
  "sources": [ { "id": "m1", "label": "我的简历.pdf", "kind": "doc" } ],
  "materialCount": 1
}
```

### 4.3 完成诊断（写入旅程状态）

`POST /api/v1/profile/diagnosis-complete`

**请求体：**
```jsonc
{
  "targetJobName": "大模型应用工程师",
  "matchPct": 62                 // 与目标岗位对标百分比 0-100
}
```

**响应 `data`：** `{ "hasDiagnosed": true }`
> 对应前端 `useJourney().completeDiagnosis({ targetJobName, matchPct })`，首页对标摘要条会回显。

### 4.4 能力画像（雷达数据）

供 Dashboard / 对标雷达图使用。

`GET /api/v1/profile/ability-portrait`

**响应 `data`：**
```jsonc
{
  "dimensions": ["机器学习基础","神经网络","深度学习","注意力机制","Transformer","大模型微调"],
  "values": [85, 72, 68, 45, 30, 20]
}
```

### 5.3 岗位匹配度 + 能力缺口（C-fix 批2，additive）
> 对应前端：`services/jobMatch.ts`、`ProfileConfirmModal.tsx`（诊断确认弹窗）。

`POST /api/v1/job-market/match`

**请求体：** `jobId` / `goal` 至少给一项。
```jsonc
{
  "jobId": "llm-app",   // 可选：直指岗位
  "goal": "想转大模型应用方向"  // 可选：学习目标自由文本（对话诊断采集），后端按关键词映射到岗位库
}
```
**响应 `data`：** 用现有静态岗位 `radar`（2.4，6 维需求）与用户能力（4.4 能力雷达 + 已掌握 Mastery 抬升对应维）对标。
```jsonc
{
  "jobId": "llm-app",
  "jobName": "大模型应用工程师",
  "matchPct": 50,               // 达标维度占比 ×100（达标 = 用户该维 ≥ 岗位需求），与岗位对标同口径
  "gaps": [                     // 未达标维度，按缺口降序
    { "dimension": "大模型微调", "level": 20, "demand": 88, "gap": 68 },
    { "dimension": "Transformer", "level": 30, "demand": 92, "gap": 62 }
  ],
  "radar": { "dimensions": ["机器学习基础", "…"], "values": [85,82,82,45,30,20], "demand": [70,72,78,85,92,88] }
}
```
> 岗位无法解析（`jobId` 不存在且 `goal` 未命中任何岗位）→ `code 1004`。`matchPct` 与
> [4.3 diagnosis-complete](#43-完成诊断) 写入 `Journey.matchPct` 同口径，使学情概览的「目标岗位 + 匹配度」有真实出处、口径一致。

> 三项比率均为 0-1 浮点，前端按百分比渲染 gauge；`adaptationRate / coverageRate` 的统计样本与计算脚本在 B8 交付阶段产出报告并接入本接口。

### 15.3 幻觉率（hallucinationRate）计算口径（缺口 #4）

[8.2 讲义](#82-生成自适应讲义核心) 与 [14.6 指标](#146-系统指标看板) 的 `hallucinationRate` 统一口径：

> **逐句接地校验**——将生成内容按句切分，每句与本次 RAG 检索命中的来源切片做 embedding 相似度比对，取最大相似度。低于阈值（默认 `0.75`）的句子视为「未接地（疑似幻觉）」。
>
> ```
> hallucinationRate = 未接地句数 / 总句数
> ```
>
> 取值 0-1，前端在 `< 0.05` 时显示「幻觉率 <5%」绿色标记。阈值可在配置中调整；无任何 RAG 来源（纯模板/兜底）时该值按约定置 `0` 并标注来源为模板，不参与质量统计。

**`POST /api/v1/resource/tutor/chat`**（`Accept: text/event-stream`）

**流式响应（`Content-Type: text/event-stream`）：**
```

data: {"delta":"问题"}

data: {"delta":"。先想一想："}

event: done
data: {"sessionId":"s_123","suggestions":["等价于线性变换","可以拟合任意函数","不确定"]}

```
> 约定：
> - 增量 token 以默认事件 `data: {"delta":"<片段>"}` 逐条下发（每条以空行 `\n\n` 分隔）。
> - 流结束发送 `event: done`，其 `data` 携带最终 `sessionId` 与 `suggestions`（对应 8.7 JSON 的同名字段）。

## 17. 对话式学习画像诊断（功能 1 增补）

> 对应前端：`frontend/src/pages/ProfileBuilder.tsx`（对话式诊断页，新增）；与第 4 章表单 + 滑块自评模式**并存**，由前端入口切换。
> 赛题功能 1 要求：「摒弃传统繁琐表单，通过自然语言对话自动抽取特征，构建不少于 6 个维度（知识基础、认知风格、易错点偏好等）的动态学生画像，并支持随学随新。」本章定义其接口契约。

> **与既有画像接口的关系（重要，二者并存、用途不同，互不替换）：**
> - [4.4 `GET /profile/ability-portrait`](#44-能力画像雷达数据)：返回**固定 6 知识点掌握度雷达**（机器学习基础 / 神经网络 / 深度学习 / 注意力机制 / Transformer / 大模型微调），供 Dashboard 对标雷达图。**本章不改动该接口，签名与语义保持原样。**
> - 本章 [17.2 StudentPortrait](#172-异质学生动态画像-studentportrait6-维) / [17.3 `GET /profile/student-portrait`](#173-获取学生画像)：返回**赛题要求的异质学生画像**（≥6 个异质维度，含认知风格、易错点偏好、学习节奏等非量化维度）。二者数据结构、维度集、用途均不同，并行维护。

### 17.1 对话式诊断（多轮 · SSE / JSON 双模式）

通过自然语言多轮对话自动抽取学生特征，逐步构建 [17.2 StudentPortrait](#172-异质学生动态画像-studentportrait6-维)。与 [8.7 苏格拉底辅导](#87-苏格拉底辅导对话式) / [15.4 SSE 格式](#154-苏格拉底辅导-sse-流式格式缺口-5) 一致：请求头携带 `Accept: text/event-stream` 时走 SSE 流式；否则返回整体 JSON（向后兼容）。

`POST /api/v1/profile/dialogue`

**请求体：**
```jsonc
{
  "sessionId": "d_123",          // 多轮上下文 id；首轮可空（null/省略），由后端生成并在响应回传
  "message": "我是计算机本科，做过Python爬虫，想转大模型应用",  // 学生本轮自然语言输入
  "context": { "major": "计算机科学", "goal": "职业培训" }      // 可选，首轮可带已知信息辅助冷启动
}
```
> `context` 字段语义复用第 4 章枚举：`major`（专业）、`goal`（目标），取值参考 [4.1 枚举参考](#41-多模态材料解析)；可缺省。

**流式响应（`Accept: text/event-stream` → `Content-Type: text/event-stream`）：**
```
data: {"delta":"了解了。"}

data: {"delta":"你提到做过爬虫——那对 HTTP 和数据解析熟到什么程度？"}

event: portrait
data: {"updates":[{"key":"prior_experience","label":"先验经验","value":"有Python工程实践(爬虫)","confidence":0.8,"source":"dialogue"}]}

event: done
data: {"sessionId":"d_123","suggestions":["很熟能独立写","会用但常查文档","基本没接触"],"diagnosisComplete":false}

```
> **SSE 约定：**
> - 默认事件 `data: {"delta":"<片段>"}` 逐条下发追问语 / 反馈语，前端按 chunk 增量渲染（每条以空行 `\n\n` 分隔）。
> - `event: portrait` 携带**本轮抽取的画像维度增量** `{"updates": PortraitDimension[]}`（结构见 [17.2](#172-异质学生动态画像-studentportrait6-维)），一次对话可多次下发（边问边抽）。前端据此实时刷新右侧画像面板。
> - `event: done` 表示本轮结束，其 `data` 携带最终 `sessionId`、`suggestions`（快捷回复建议，可空）、`diagnosisComplete`（布尔，是否已采集到足够维度可结束诊断）。
> - 出错发送 `event: error`，`data: {"code":2001,"message":"..."}`，前端回退提示并**保留已渲染片段与已抽取维度**。
> - 会话上下文按 `sessionId` 在后端内存中按 TTL 维持（同 8.7 / 15.4 约定）。

**非流式响应 `data`（不带 `Accept: text/event-stream` 时）：**
```jsonc
{
  "sessionId": "d_123",
  "reply": "了解了。你提到做过爬虫——那对 HTTP 和数据解析熟到什么程度？",
  "portraitUpdates": [           // 本轮抽取的画像维度增量（= SSE 各 event:portrait 的 updates 合并）
    { "key": "prior_experience", "label": "先验经验", "value": "有Python工程实践(爬虫)", "confidence": 0.8, "source": "dialogue" }
  ],
  "suggestions": ["很熟能独立写", "会用但常查文档", "基本没接触"],  // 快捷回复建议，可空
  "diagnosisComplete": false
}
```
> JSON 模式字段与 SSE 终态等价：`reply` ≡ 各 `delta` 拼接；`portraitUpdates` ≡ 各 `event:portrait` 的 `updates` 合并；`sessionId` / `suggestions` / `diagnosisComplete` ≡ `event:done` 的 `data`。两种模式均套用 [1.2 统一响应信封](#12-统一响应信封)（SSE 的 `event:error` 中 `code/message` 与信封错误码一致）。

> **业务约束（防幻觉，必须遵守）：**
> - 无法从对话明确判断的维度**不得编造**——宁可不下发该维度的 `update`，也不臆测具体值。
> - `source` 取值 `dialogue | manual | inferred`：`dialogue` = 对话中明确陈述；`manual` = 学生在表单/选项中显式填写；`inferred` = 由对话间接推断。
> - `inferred`（推断）维度**必须给较低 `confidence`**（建议 ≤ 0.6），与 [4.2 接地约束](#42-画像叙述生成接地版-ai-总结) 的防幻觉原则一致。

### 17.2 异质学生动态画像 StudentPortrait（≥6 维）

赛题功能 1 要求的**异质学生画像**数据结构，由 [17.1 对话式诊断](#171-对话式诊断多轮--sse--json-双模式) 增量构建、随学习/测验更新（随学随新）。

**StudentPortrait：**
```jsonc
{
  "dimensions": [                // PortraitDimension[]，≥6 维（异质：含可量化与非量化维度）
    { "key": "knowledge_base",   "label": "知识基础",   "value": "一般",              "score": 65, "confidence": 0.7, "source": "dialogue", "updatedAt": "2026-06-15T10:00:00+08:00" },
    { "key": "cognitive_style",  "label": "认知风格",   "value": "偏实践/动手型",      "confidence": 0.6, "source": "dialogue" },
    { "key": "error_preference", "label": "易错点偏好", "value": "概念易混淆",         "confidence": 0.5, "source": "inferred" },
    { "key": "learning_goal",    "label": "学习目标",   "value": "转大模型应用工程师", "confidence": 0.9, "source": "dialogue" },
    { "key": "prior_experience", "label": "先验经验",   "value": "Python爬虫工程经验", "confidence": 0.8, "source": "dialogue" },
    { "key": "learning_pace",    "label": "学习节奏",   "value": "适中",              "confidence": 0.6, "source": "dialogue" }
  ],
  "version": "v1",
  "updatedAt": "2026-06-15T10:00:00+08:00"   // 画像整体最近更新时间
}
```

**PortraitDimension（单个维度，亦即 17.1 `portraitUpdates[]` / `event:portrait` 的 `updates[]` 元素）：**
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `key` | string | 是 | 维度键名（稳定标识，见下方建议维度集） |
| `label` | string | 是 | 维度中文显示名 |
| `value` | string | 是 | 维度取值（自然语言描述，如「偏实践/动手型」） |
| `score` | number | 否 | 仅**可量化维度**（如知识基础）给出，0-100；其余维度省略 |
| `confidence` | number | 是 | 置信度 0-1；`inferred` 维度须偏低（建议 ≤ 0.6） |
| `source` | string | 是 | `dialogue \| manual \| inferred`（见 17.1 防幻觉约束） |
| `updatedAt` | string | 否 | 该维度最近更新时间（ISO 8601）；体现「随学随新」 |

> **建议维度集（≥6，`key` 稳定，`value` 由对话/学习填充）：** `knowledge_base`(知识基础) · `cognitive_style`(认知风格) · `error_preference`(易错点偏好) · `learning_goal`(学习目标) · `prior_experience`(先验经验) · `learning_pace`(学习节奏)。后端可在保持 `key` 稳定的前提下扩展更多维度。
> **随学随新：** 学习/测验完成后（如 9.1 测验通过、8.2 讲义学习）可回写对应维度（典型为 `knowledge_base` 的 `score` 与 `value`），并刷新该维度 `updatedAt` 与画像整体 `version`/`updatedAt`。

### 17.3 获取学生画像

返回当前用户最新版本的 [17.2 StudentPortrait](#172-异质学生动态画像-studentportrait6-维)，供对话式诊断页右侧实时展示，亦供后续个性化资源生成读取。

`GET /api/v1/profile/student-portrait`

**响应 `data`：** 即 [17.2 StudentPortrait](#172-异质学生动态画像-studentportrait6-维) 完整结构。

> 画像随 [17.1 对话](#171-对话式诊断多轮--sse--json-双模式) 与学习行为更新；本接口始终返回当前最新版本。尚无任何对话/诊断数据时，返回 `dimensions: []` 的空画像（`version` 为 `"v1"`、`updatedAt` 为创建时间），前端展示「尚未开始诊断」占位，不视为错误。

### 17.4 覆盖写入学生画像（追加 · C-fix）

> **新增接口（不改动既有任一签名/字段）。** 背景：画像诊断有三条产出路径——[17.1 对话诊断](#171-对话式诊断多轮--sse--json-双模式)（边问边抽，经 SSE `event: portrait` 增量写入）、**简历分析**、**手动填写**（均在 `ProfileBuilder.tsx`「确认画像」时确定）。三条路径必须写入**同一份权威画像（[17.2 StudentPortrait](#172-异质学生动态画像-studentportrait6-维)，同一套 canonical 维度 key）**，不得各造一套雷达。对话路径已有写入通道（17.1）；本接口为**简历 / 手动路径**提供整份覆盖写入通道。

`PUT /api/v1/profile/student-portrait`

**请求体：**
```jsonc
{
  "dimensions": [          // 已映射为 17.2 canonical 维度（与对话诊断同一套 key）的整份画像
    { "key": "knowledge_base", "label": "知识基础", "value": "人工智能背景，能力自评均值 60", "score": 60, "confidence": 0.7, "source": "manual" },
    { "key": "prior_experience", "label": "先验经验", "value": "硕士 · 人工智能", "confidence": 0.7, "source": "manual" },
    { "key": "learning_goal", "label": "学习目标", "value": "职业培训", "confidence": 0.8, "source": "manual" },
    { "key": "error_preference", "label": "易错点偏好", "value": "大模型微调偏薄弱", "confidence": 0.5, "source": "inferred" },
    { "key": "cognitive_style", "label": "认知风格", "value": "待对话诊断补全", "confidence": 0.4, "source": "inferred" },
    { "key": "learning_pace", "label": "学习节奏", "value": "待对话诊断补全", "confidence": 0.4, "source": "inferred" }
  ]

```
> 维度元素结构同 [17.2 PortraitDimension](#172-异质学生动态画像-studentportrait6-维)（`updatedAt` 由服务端统一加盖，可不带）。表单未直接采集的维度（认知风格 / 学习节奏）标 `source: "inferred"` + 低置信度（防杜撰，留待对话补全）。

**响应 `data`：** 即 [17.2 StudentPortrait](#172-异质学生动态画像-studentportrait6-维) 完整结构（写入后的整份画像）。

## 18. 学习流程模块（费曼 + 康奈尔）Learning Flow

> 对应前端：学习流程页（`frontend/src/pages/LearningResource.tsx` 学习闭环子流程；康奈尔笔记区 + 费曼讲解区 + 步骤进度条）。

> **红线：** 本章仅新增 `/learning/*` 接口与两张轻量存储表，**不改动第 1–17 章任一接口签名/字段**；「已掌握」判定仍由 [9.1 测验提交](#91-获取测验题--提交)（≥60 分）驱动 [7.3 Mastery 标记通过](#73-标记知识点已通过)，本章不新增任何掌握度判定路径。

### 18.1 康奈尔线索生成

为指定知识点生成**康奈尔笔记法**所需的「线索区」问题/关键词（5–8 条）与「主笔记区」要点预填骨架，供学习者带着问题做主动笔记。

`POST /api/v1/learning/cornell-cues`

**请求体：**
```jsonc
{
  "kpId": "nn",
  "difficulty": "初级"      // 入门|初级|高级，与 8.2 讲义难度档一致；缺省「初级」
}
```

**响应 `data`（CornellCues）：**
```jsonc
{
  "kpId": "nn",
  "difficulty": "初级",
  "cues": [                          // 线索区：5–8 条关键问题/关键词（康奈尔左栏）
    { "id": "c1", "type": "question", "text": "为什么神经网络需要激活函数？" },
    { "id": "c2", "type": "question", "text": "前向传播与反向传播分别解决什么问题？" },
    { "id": "c3", "type": "keyword",  "text": "加权求和 → 偏置 → 激活" }
    // type: question(线索问题) | keyword(关键词)
  ],
  "noteOutline": [                   // 主笔记区预填项：与 cue 对应的要点骨架（康奈尔右栏初始内容）
    {
      "id": "n1",
      "cueId": "c1",                 // 关联的线索 id，可为 null（通用要点）
      "heading": "激活函数的作用",
      "points": ["引入非线性表达能力", "若无激活，多层网络等价于单层线性变换"]
    }
  ],
  "summaryHint": "用一句话概括：神经网络如何通过逐层加权与非线性激活拟合复杂函数？",  // 总结区引导语，可空
  "sources": [                       // RAG 引用，结构同 8.2 sources（供 SourceTrace 展示），可空
    { "title": "《深度学习》花书 第6章", "type": "教材", "confidence": 0.9 }
  ]
}
```
> `cues` 数量约束 **5–8 条**；`type` 取值 `question | keyword`。`noteOutline` 为可编辑初值，前端载入主笔记区后用户继续补充（最终内容经 [18.5 保存笔记](#185-保存康奈尔笔记) 持久化）。
> 经 `LLMClient` 按 kp + 难度生成：**mock provider 无密钥即给与知识点相关的确定性线索/骨架**，deepseek 模式真实生成、解析失败回落占位骨架（同 8.3 视频脚本降级口径）。`kpId` 非法 → `code 1004 / HTTP 404`；难度档非法 → `code 1001 / HTTP 400`（同 8.2/11.1 口径）。

### 18.2 费曼讲解评估（SSE / JSON 双模式）

学习者用自己的话「讲解」某知识点，系统**点评 + 追问**以暴露理解漏洞，结束时给出 `gaps[]`（识别出的知识缺口，并关联应回看的资源 / 知识点）。与 [8.7 苏格拉底辅导](#87-苏格拉底辅导对话式) / [15.4 SSE 格式](#154-苏格拉底辅导-sse-流式格式缺口-5) / [17.1 对话式诊断](#171-对话式诊断多轮--sse--json-双模式) 同体例：请求头携带 `Accept: text/event-stream` 时走 SSE 流式；否则返回整体 JSON（向后兼容）。

`POST /api/v1/learning/feynman`

**请求体：**
```jsonc
{
  "kpId": "nn",
  "sessionId": "f_123",          // 多轮上下文 id（支持「补讲—再评」迭代）；首轮可空，由后端生成并回传
  "explanation": "神经网络就是一堆神经元，每个把输入乘上权重加起来，然后输出。"  // 学生本轮讲解文本
}
```

**流式响应（`Accept: text/event-stream` → `Content-Type: text/event-stream`）：**
```
data: {"delta":"你抓住了「加权求和」这一步，"}

data: {"delta":"但有个关键环节被跳过了——你没提到激活函数。"}

event: gaps
data: {"gaps":[{"id":"g1","kpId":"nn","title":"遗漏激活函数（非线性）","detail":"讲解中只到加权求和，未提到激活函数，而非线性正是神经网络区别于线性模型的核心。","severity":"high","review":[{"kind":"lecture","title":"《神经网络基础》自适应讲义","kpId":"nn","endpoint":"/resource/lecture","difficulty":"初级"},{"kind":"diagram","title":"神经网络基础 · 知识图解","kpId":"nn","endpoint":"/resource/diagram"}]}]}

event: done
data: {"sessionId":"f_123","score":72,"followups":["如果去掉激活函数，三层网络和一层有什么区别？"],"complete":false}

```
> **SSE 约定（与 15.4 / 17.1 一致）：**
> - 默认事件 `data: {"delta":"<片段>"}` 逐条下发点评 / 追问语，前端按 chunk 增量渲染（每条以空行 `\n\n` 分隔）。
> - `event: gaps` 携带本轮识别出的知识缺口 `{"gaps": Gap[]}`（结构见下），通常在讲解末尾下发一次；前端据此高亮「待回看」清单。
> - `event: done` 表示本轮结束，其 `data` 携带最终 `sessionId`、`score`（讲解完整度评分 0-100，可空）、`followups`（追问/补讲引导，可空）、`complete`（布尔，是否讲解充分可结束：`gaps` 为空或仅 `low` 时为 `true`）。
> - 出错发送 `event: error`，`data: {"code":2001,"message":"..."}`，前端回退提示并保留已渲染片段与已识别缺口。
> - 会话上下文按 `sessionId` 在后端内存中按 TTL 维持（同 8.7 / 15.4 / 17.1 约定）。

**Gap（知识缺口，亦即 SSE `event:gaps` 的 `gaps[]` 元素 / JSON 的 `gaps[]` 元素）：**
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 缺口 id（本轮内稳定） |
| `kpId` | string | 是 | 缺口所属知识点（通常 = 本 kp，也可指向相关先修 kp） |
| `title` | string | 是 | 缺口标题（简述漏讲/误解的点） |
| `detail` | string | 是 | 缺口说明（为什么这是缺口） |
| `severity` | string | 是 | `high \| medium \| low`（影响理解的严重度） |
| `review` | object[] | 否 | 建议回看的资源，元素结构**复用 [6.3](#63-真实规划增量向后兼容仅追加不重排) `resources[]`**：`{ kind, title, kpId, endpoint, difficulty? }`，指向真实资源端点（可点开） |

**非流式响应 `data`（不带 `Accept: text/event-stream` 时）：**
```jsonc
{
  "sessionId": "f_123",
  "feedback": "你抓住了「加权求和」这一步，但跳过了激活函数。",  // ≡ 各 delta 拼接
  "score": 72,                    // 讲解完整度评分 0-100，可空
  "gaps": [ /* Gap[]，见上；≡ SSE 各 event:gaps 的 gaps 合并 */ ],
  "followups": ["如果去掉激活函数，三层网络和一层有什么区别？"],  // 追问，可空
  "complete": false               // 是否讲解充分可结束
}
```
> JSON 模式字段与 SSE 终态等价：`feedback` ≡ 各 `delta` 拼接；`gaps` ≡ 各 `event:gaps` 的 `gaps` 合并；`sessionId` / `score` / `followups` / `complete` ≡ `event:done` 的 `data`。两种模式均套用 [1.2 统一响应信封](#12-统一响应信封)（SSE 的 `event:error` 中 `code/message` 与信封错误码一致）。
> **业务约束（防幻觉）：** 缺口须**基于学生讲解文本与 RAG 来源**判定，不得编造学生未涉及亦非本 kp 核心的「缺口」；`review` 仅指向系统已有的真实资源端点（同 6.3 资源指向口径）。生成失败 → `code 2001`。

### 18.3 学习步骤进度

记录某知识点下各学习步骤的完成状态。步骤集固定 6 项：`video`(视频) · `lecture`(讲义) · `diagram`(图解) · `note`(笔记) · `feynman`(费曼) · `practice`(实操)。

> **设计取舍（为何不直接复用 Mastery）：** [7.x Mastery](#7-掌握度与学习旅程-mastery--journey) 仅建模知识点三态（`learning / pending-check / passed`），**粒度不足以表达 6 个过程步骤的逐项完成**；故步骤进度落在轻量表 `LearningStepProgress`（见 [18.6](#186-数据存储增补复用与新增说明)），与 Mastery 解耦。**步骤完成 ≠ 已掌握**：本接口的 6 步是「过程完成标记」，「已掌握」仍由阶段测试（[9.1](#91-获取测验题--提交) ≥60 分）驱动 Mastery（[7.3](#73-标记知识点已通过)）——响应中以 `mastery` 字段**透传** 7.1 的该 kp 掌握态，前端「已掌握」徽标以此为准，不取决于 `practice` 步骤是否勾选。

**获取：** `GET /api/v1/learning/steps/{kpId}`

**响应 `data`：**
```jsonc
{
  "kpId": "nn",
  "steps": {                       // Record<stepKey, boolean>；未出现的步骤视为未完成
    "video": true,
    "lecture": true,
    "diagram": false,
    "note": false,
    "feynman": false,
    "practice": false
  },
  "mastery": "learning",           // 透传 7.1 该 kp 掌握状态（learning|pending-check|passed），"已掌握" 以此为准
  "completedCount": 2,             // 已完成步骤数
  "total": 6,
  "updatedAt": "2026-06-16T10:00:00+08:00"
}
```

**更新：** `POST /api/v1/learning/steps/{kpId}`（幂等）

```jsonc
// 请求
{
  "step": "feynman",              // video|lecture|diagram|note|feynman|practice
  "done": true                    // 置为完成 / 取消完成
}
```
**响应 `data`：** 同「获取」的最新整体进度（含刷新后的 `completedCount` 与 `mastery`）。
> 非法 `step`（不在 6 项内）→ `code 1001 / HTTP 400`；`kpId` 非法 → `code 1004 / HTTP 404`。
> **联动建议（前端调用时机，非后端强约束）：** [18.2 费曼](#182-费曼讲解评估sse--json-双模式) 评估 `complete=true` 后置 `feynman=true`；[18.5 保存笔记](#185-保存康奈尔笔记) 成功后置 `note=true`。`practice`（实操/阶段测试）步骤完成与否由前端勾选，**而该 kp 是否「已掌握」独立地由 [9.1 测验提交](#91-获取测验题--提交) 驱动**——后端无需在本接口内做掌握度推进。

### 18.4 获取康奈尔笔记

`GET /api/v1/learning/notes/{kpId}`

**响应 `data`（CornellNote）：**
```jsonc
{
  "kpId": "nn",
  "cueNotes": [                    // 线索区：用户对各 cue 的作答 / 批注（可由 18.1 cues 初始化）
    { "cueId": "c1", "text": "为引入非线性，否则等价线性变换" }
  ],
  "mainNotes": "## 激活函数\n- 引入非线性\n- ReLU / Sigmoid …",   // 主笔记区：Markdown 自由编辑（可由 18.1 noteOutline 预填）
  "summary": "神经网络通过逐层加权与非线性激活拟合复杂函数。",        // 总结区
  "updatedAt": "2026-06-16T10:00:00+08:00"
}
```
> 该 kp 尚无笔记时返回**空笔记**（`cueNotes: []`、`mainNotes: ""`、`summary: ""`、`updatedAt` 为创建时间），前端展示空白康奈尔模板，**不视为错误**（同 17.3 空画像口径）。

### 18.5 保存康奈尔笔记

`PUT /api/v1/learning/notes/{kpId}`（整体覆盖保存，幂等）

```jsonc
// 请求（= CornellNote 去除 updatedAt，由服务端盖戳）
{
  "cueNotes": [ { "cueId": "c1", "text": "为引入非线性" } ],
  "mainNotes": "## 激活函数\n- 引入非线性 …",
  "summary": "神经网络通过逐层加权与非线性激活拟合复杂函数。"
}
```
**响应 `data`：** 保存后的 CornellNote（`updatedAt` 刷新），结构同 [18.4](#184-获取康奈尔笔记)。
> `kpId` 非法 → `code 1004 / HTTP 404`。保存成功前端可顺带置 [18.3](#183-学习步骤进度) `note=true`。

### 18.6 数据存储增补（复用与新增说明）

> 回答「笔记 / 步骤进度存前端本地还是轻量持久化」与「现有 quiz 判分能否直接驱动 Mastery」两问，明确复用边界。

**1）复用（不新增、不改动）：**
- **「已掌握」判定完全复用既有链路**：[9.1 `POST /quiz/{kpId}/submit`](#91-获取测验题--提交) 在 `score≥60` 时已返回 `masteryUpdated: { id, status:"passed" }`，其语义**即** [7.3 `POST /mastery/{kpId}/pass`](#73-标记知识点已通过)。**对接方式：** 学习流程页的「实操 / 阶段测试」步骤直接调用既有 9.1，测验通过即 Mastery 自动推进至 `passed`；学习流程页读取 [7.1 `GET /mastery`](#71-获取掌握度全集)（或 [18.3](#183-学习步骤进度) 透传的 `mastery` 字段）渲染「已掌握」。**结论：现有 quiz 判分可直接驱动 Mastery，无需任何新增判定逻辑或字段。**
- `Journey`（7.4）/ `Mastery`（7.1）**表结构与接口逐字不变**。

**2）新增（轻量持久化，建议而非前端本地）：**
> **建议：笔记与步骤进度采用后端轻量持久化（SQLite），不放前端 localStorage。** 理由：① 满足「随学随新」跨设备/换浏览器不丢；② 笔记与画像（[17.2](#172-异质学生动态画像-studentportrait6-维) 随学随新）可作为后续个性化资源生成的输入；③ 与项目轻量栈一致（SQLite，不引入额外存储中间件）。

新增两张轻量表（仅本章使用，主键含 `userId`，与现有表无外键耦合）：

| 表 | 关键字段 | 说明 |
|---|---|---|
| `LearningStepProgress` | `(userId, kpId, step)` 联合唯一、`done` bool、`updatedAt` | 支撑 [18.3](#183-学习步骤进度) 步骤进度；`step ∈ {video,lecture,diagram,note,feynman,practice}` |
| `LearningNote` | `(userId, kpId)` 联合唯一、`cueNotes`(JSON)、`mainNotes`(TEXT)、`summary`(TEXT)、`updatedAt` | 支撑 [18.4](#184-获取康奈尔笔记) / [18.5](#185-保存康奈尔笔记) 康奈尔笔记 |

> 两表均按当前登录用户隔离（`userId` 取自 token，同第 16 章口径）；费曼会话（18.2）按 `sessionId` 走内存 TTL，**不落表**（与 8.7 / 17.1 一致）。生产替换路径（如迁 PostgreSQL）写入 README，不在 demo 内实现。
