> **铁律：这是平行独立线，绝不改动现有内置 AI 课程的画像/诊断/学习路径/掌握度。复用现有 RAG 与生成引擎，不重造。**

# 范围锁定（严格遵守，别膨胀）

# 角色

# 先查并报告
现有 RAG 管线（chunker/embedding/Chroma/检索）怎么组织的？现有讲义/视频/图解/思维导图/练习题生成函数的入参是什么（是否绑定"内置知识点 kp_id"，还是可传入任意文本/来源）？要接文档学习，生成函数需要怎样以"文档来源"驱动？

# 任务
1. **文档上传 + 解析**：新增接口接收上传的 PDF / 文本/markdown，解析出文本内容（PDF 抽文本）；大文档分块。新增"文档/笔记本"实体（user_id 归属、文档元数据、解析文本、关联的向量集合）。
2. **临时知识库（隔离）**：把上传文档的分块灌入一个**该文档专属的向量集合/命名空间**（Chroma collection 隔离），**与内置课程知识库分开**，互不污染。
3. **基于文档生成（复用引擎）**：新增生成接口，以"文档来源"为知识源，调用现有生成能力产出：讲义、视频（分镜）、图解、思维导图、练习题——把原来"按内置 kp_id 检索"改为"按该文档的向量集合检索 + 生成"。**生成/审核/防幻觉/内容安全全部复用，不重造**。
4. **闪卡（新做）**：新增闪卡生成——从文档内容/讲义要点抽成"正面问题 / 背面答案"的卡片集（走 LLMClient，mock 确定性兜底）。
5. **接资源库**：文档学习生成的内容也写入 GenerationLog（带 user_id + 文档来源标识），进"我的资源库"。
6. 接口全部套统一信封、追加进接口文档；Mock 兜底（无 Key 用确定性 mock 解析/生成）。

# 约束
- **绝不改动现有内置课程的画像/诊断/路径/掌握度/既有生成接口签名**；文档学习是新增的平行链路。
- 复用现有 RAG、生成 Agent、Critic、内容安全、TTS；向量集合与内置库隔离。
- PDF 解析用成熟库（如 pypdf/pdfplumber）；大文档合理分块。

# 验证（实测）
1. 上传一个 PDF 和一个 md → 成功解析、分块入该文档专属向量集合；
2. 基于该文档生成讲义/图解/练习题/闪卡 → 内容确实来自上传文档（不是内置课程），防幻觉/内容安全生效；
3. 生成内容进资源库、带文档来源标识；
4. 内置课程主线功能不受影响（回归）；全量测试通过、mock 可跑。

# 输出
现状说明 + 数据/接口设计 + 改动文件清单 + 接口文档增量 + 验证结果 + 红线自检。完成即停。
