## 任务 1：讲义生成增强（更专业、更深入、贴画像）
优化讲义生成 Agent 的 prompt（mock 与真实双模式都要相应增强），让任何难度档的讲义都做到：
- **结构递进**：按"概念引入 → 核心原理 → 具体例子 → 代码示例 → 常见误区 → 小结"的递进结构组织，不要平铺罗列。
- **更多例子与代码**：每个关键概念**至少配一个具体例子**；涉及算法/实现的**给可运行代码片段**（带注释、说明输入输出），不要只有文字描述。
- **贴画像给不同深度**（关键个性化）：读取当前用户**能力画像**——
  - 能力强：给进阶细节、公式推导、底层原理、对比延伸；
  - 零基础：多用类比、少堆术语、步骤更细、先直觉后形式化；
  - 让同一知识点对不同用户产出**深度不同的讲义**。
- **专业度**：内容要像一份真正的课程讲义，而非维基摘要——有深度、有逻辑、有"为什么"。

## 任务 2：公式格式修复（硬伤）
- 现状：生成的公式格式乱、渲染不正确。
- 先查：讲义里公式现在怎么输出和渲染的？是否缺数学渲染库、LaTeX 分隔符不规范？
- 修复：
  - 生成端 prompt 明确要求用**标准 LaTeX 语法**（行内 `$...$`、独立公式 `$$...$$`，规范转义）；
  - 前端接入 **KaTeX（或 MathJax）** 正确渲染行内与块级公式；
  - 验证常见公式（如 softmax、注意力 QK^T/√d、梯度下降等）渲染正确、不再乱。

## 任务 3：知识图解丰富化（修"每次生成都一样"）
- 现状：图解太单一、每次生成内容一致——疑似 mock 写死或 prompt 太固定。
- 先查：图解是真按知识点/讲义内容动态生成，还是写死/固定模板？
- 修复：
  - 让图解**真正基于该知识点的内容结构动态生成**，不同知识点产出不同图解；
  - **形式更丰富**：根据内容选用合适的图型（流程图/层次图/关系图/对比图等 Mermaid 类型），不要永远一种；
  - mock 模式也要按知识点产出不同图解（复用刚补的 kpResources 思路）。

# 约束
复用现有讲义/图解生成链路与 Critic；只增强 prompt 与渲染，不改接口签名（如需新增仅追加并同步文档）；防幻觉/内容安全机制不能绕过；Mock 兜底。

# 验证（截图）
1. 讲义：同一知识点对"能力强"和"零基础"两个用户 → 产出**深度明显不同**的讲义；都含例子 + 代码 + 递进结构；
2. 公式：含公式的讲义渲染正确、不乱（贴渲染截图）；
3. 图解：不同知识点 → 不同图解；同知识点不再每次完全一致、形式合理；
4. 既有接口零回归、内容安全/防幻觉不破、全量测试通过、tsc 干净。

# 输出
现状说明 + 改动文件清单 + 接口文档增量（如有）+ 验证结果（含两用户讲义深度对比 + 公式渲染截图）+ 红线自检。完成即停。
