# 文档维护规则

**维护类型：实时维护**

## 生命周期分类

### A. 权威契约

描述系统必须满足什么，包括接口、类型、需求和团队纪律。必须保持最新，变更需同步代码与测试。

### B. 当前状态

描述系统现在是什么、有哪些边界、下一步做什么。持续覆盖更新，不保留逐日流水账。

### C. 专题基线

描述某个相对稳定的设计主题，例如知识体系、算法形式化、Agent 架构和多模态方案。设计发生实质变化时更新。

### D. 阶段日志

记录某次任务的文件清单、验证命令和实际结果。创建后固化，不因后续实现变化而改写。

### E. 过程资产

CC 指令、旧方案、评审草稿、改前改后记录和历史 PPT 方案。仅供追溯，统一归档。

### F. 构建与交付资产

PPT、DOCX、PDF、截图、录屏素材和压缩包。指定当前版与来源，能再生的中间产物不作为事实依据。

## 命名规则

- 当前维护文档使用稳定名称，不添加 `最终版`、`最新版`。
- 阶段日志使用 `B<N>.md`、`C<N>.md`、`feat-主题.md` 或 `fix-主题.md`。
- 历史方案保留原文件名，移动到归档目录即可。
- 同一文档不再创建 `v2-final-最终修改版`；使用 Git 保存版本历史。
- 新任务不要创建 `CC-*.md` 作为长期入口。任务完成后写标准阶段日志。

## 合并规则

- 多份“当前进度”只保留一份实时状态，旧清单归档。
- 多份“产品定位/创新点”合并为当前项目叙事；旧版本归档。
- CC 指令与完成总结重复时，以完成总结作为验收证据，指令归档。
- PPT 修改方案、改动说明和旧版 PPT 放在同一交付资产组，不参与开发事实裁决。

## 删除规则

可直接删除：

- Office 锁文件 `~$*`。
- 0 字节失败产物。
- 已确认可重新生成且没有验收价值的临时缓存。
- 内容和哈希完全相同的重复副本，保留路径更规范的一份。

需先归档再删除：

- CC 指令和旧设计方案。
- 旧版进度清单。
- 曾用于答辩、验收或争议定位的截图和报告。

不得自动删除：

- 权威契约和需求原文。
- 当前版 PPT、技术文档、答辩稿和演示脚本。
- 用户尚未提交或正在编辑的文件。
- 证件、报名材料等敏感资料；应由资料负责人移出代码仓库。

## 阶段收尾模板

```markdown
# <阶段/任务名称>

- 日期：
- 状态：完成 / 部分完成 / 阻塞
- 契约依据：

## 文件变更

## 行为变化

## 验证

## 已知限制

## 后续动作
```

## 文档审查清单

- 链接存在且没有指向已移动文件。
- 当前状态与代码、测试、实际回包一致。
- 没有把真实 Key、手机号、邮箱写入文档。
- 没有复制大段代码作为“技术文档”。
- 历史日志和当前状态明确分开。
- 只维护一个当前版，不通过文件名堆版本。
