# 角色
资深前端 + 全栈工程师。项目已联调，禁改既有接口签名。本会话重做画像诊断界面并新增两种诊断入口。

# 任务 1：修复诊断界面布局（又挤又窄、回答被题目遮挡）
**现象**：对话画像界面太小，题目/提问把用户的回答内容遮挡了，整体又挤又窄。
**先查并报告**：当前诊断对话容器宽高、题目与回答区的布局关系，定位"回答被遮挡"是输入框浮层重叠还是容器过窄导致内容挤压。
**修复**：
- 放大诊断对话容器（合理的最大宽度 + 充足高度），内容区不再拥挤；
- 题目区与回答区**布局分明、不重叠**——回答内容完整可见，不被题目/输入框盖住；
- 微测题目、偏好选择题、对话气泡都有清晰的视觉分区与呼吸感；移动端正常。

# 任务 2：三种诊断入口（用户自选）
在诊断起点提供三选一，**三种产出同一套画像结构（能力 ability + 偏好 preference），仅来源与置信度不同**：

1. **做题式诊断（保留现有）**：对话 + 诊断微测 + 偏好选择（会话一已做）。画像来源标 **"实测 · 高置信"**。
2. **一段话描述（复用现有 /profile/parse）**：用户用自然语言描述自己的水平与目标（如"我会 Python，神经网络只懂概念，Transformer 没碰过"）→ **复用现有画像解析能力**把描述解析成同一套能力+偏好画像 → 生成画像报告。画像来源标 **"自述 · 中置信"**（自陈推断，非实测）。
3. **直接跳过 → 零基础**：一键跳过问答，直接产出**零基础默认画像**（各知识点未掌握、能力低基线），路径从头学。画像来源标 **"未测 · 默认零基础"**。

# 任务 3：画像来源与置信度标注
- 画像报告 / 学情概览里**明确标注本画像的来源与置信度**（实测·高置信 / 自述·中置信 / 未测·默认零基础）；
- 复用会话一的 source/confidence 字段（diagnostic / 新增 self_report / default 之类），不另造一套；
- 让用户清楚"这份画像有多可信"，也便于答辩讲"尊重不同习惯、如实标注可信度"。

# 约束
- 三入口产出**统一画像结构**（能力打分 + 偏好类型 + 主观信息），下游 planner/概览读法不变、不回归；
- "一段话描述"复用 /profile/parse，"跳过零基础"复用现有覆盖写；不改既有接口签名（新增仅追加并同步文档）；
- 零基础默认画像要和问题1修复一致：路径全节点未开始、不出现"已完成"；
- Mock 兜底；深浅主题正常。

# 验证（截图）
1. 诊断界面不再拥挤、回答内容完整可见不被遮挡；移动端正常；
2. 三入口可选；分别走通：
   - 做题式 → 实测画像（高置信）；
   - 一段话描述 → 解析出能力+偏好画像 + 报告（中置信，标"自述"）；
   - 跳过 → 零基础画像（标"未测/默认"），路径从头学、无"已完成"节点；
3. 三种产出的画像结构一致，下游概览/路径都能正常消费、无回归；
4. 来源置信度标注正确显示；全量测试通过、tsc 干净、0 console error。

现状说明 + 改动文件清单 + 接口文档增量（如有）+ 验证结果（含三入口各一次）+ 红线自检。完成即停。

- "跳过→零基础"要和刚修的问题1一致：零基础路径全节点未开始，绝不出现"已完成"。
