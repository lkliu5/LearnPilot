# 知识体系录入（78 点 / 7 板块）+ 诊断适配 · 完成总结（会话一）

> 承接《AI知识体系设计-v3》与《docs/归档/任务指令/CC-knowledge-system-graph-path.md》会话一。**只录结构与元信息，内容由生成引擎按需产出。** 会话二（图谱分层可视化）/ 会话三（路径细化+时间线）在此之上另做。

## 一、现状勘察（录入前）

- **知识点表** `knowledge_points`：仅 5 列 `id / name / lesson_seq / graph_node_id / description`，固定 6 核心点（`ml/nn/dl/cnn/transformer/finetune`）。**无 category/level/prerequisites**——先修关系此前不存在。
- **诊断**：`diagnostic_microtest.select_microtest` 遍历全表逐点取 1 道客观题（仅 6 核心有题库）；三段式对话诊断（`profile_dialogue`）微测段产出 `knowledge_base` 能力维 + 写 Mastery 低置信基线。
- **画像/掌握度/路径读知识点的隐式假设**：`query(KnowledgePoint).all()` 默认即 6 核心——能力雷达（4.4）取 lesson_seq 升序 6 轴、学习路径（6.2）遍历全表建步、掌握度覆盖率（12.1）分母取全表、旅程 review 判定取全表。**扩充到 78 点若不收窄，这些链路全部回归**（路径变 78 步、覆盖率分母变 78、雷达轴错位）。

## 二、数据结构设计（最小侵入·向后兼容）

`KnowledgePoint` **追加 5 列**（旧 4 字段与 8.1/2.1 契约不变；SQLite `ADD COLUMN` 幂等迁移，既有 6 行 `is_core` DEFAULT 1）：

| 列 | 类型 | 说明 |
|---|---|---|
| `code` | VARCHAR(16) | 体系编码（78 点唯一）。6 核心映射：ml→ML-1 / nn→DL-1 / dl→DL-4 / cnn→DL-6 / transformer→LLM-2 / finetune→LLM-5 |
| `category` | VARCHAR(16) | 板块码 ML/DL/CV/LLM/GEN/AGT/RLX（7 板块，RL·X 合并为 RLX） |
| `level` | VARCHAR(16) | 层级 入门\|进阶\|前沿 |
| `prerequisites` | JSON | 先修知识点 **id 列表**（种子时由体系 code 解析为 id，跨板块交叉亦然） |
| `is_core` | BOOLEAN | 6 已验证基准点=True；其余 72 目录点=False |

**核心收窄机制**：新增 `knowledge_catalog.core_kps/core_kp_ids` 作为「6 已验证基准点」的统一入口，替换 8 处 `query(KnowledgePoint).all()` 隐式假设——扩充后既有链路语义/分母不变、零回归。72 目录点只供体系浏览 + 先修推断，不进 6 点闭环。

## 三、录入方式（种子脚本·幂等）

- 78 点定义集中在 `services/knowledge_catalog.py` 的 `CATALOG`（code/name/category/level/先修/简介）+ `BOARDS`（7 板块）+ `CORE_ALIASES`（6 核心→体系编码）。
- `knowledge_catalog.seed(db)`（由 `init_db._seed_catalog` 调用，`_seed_knowledge_points` 之后）：**6 核心行原地补元信息**（不动 name/lesson_seq/graph_node_id/description，保留已生成内容与测试基准）；**其余 72 点新建**（is_core=False，lesson_seq 取 1000+ 高位序排在 6 核心之后，graph_node_id=code 避免污染 10.1 图谱 12 节点）。先修按 code 书写、seed 解析为 id（`DL-1`→`nn`）。**可重复执行**：已存在则刷元信息、不重复插入。

## 四、诊断适配说明（沿用原逻辑）

1. **微测只对核心点**：`select_microtest` 收窄到 `core_kps`（复用现有 quiz 题库，不为 78 点全出题）。
2. **先修推断**：`infer_prerequisite_closure(mastered_ids, prereq_map)`——已测得掌握（passed 或能力分≥70）的点，其**先修传递闭包**大致掌握，减少诊断负担（纯图遍历、确定性、Mock 可跑）。
3. **板块级画像**：`board_coverage(db, status_map, score_map)` 产出 7 板块 `{total, tested, inferred, covered, coveragePct}`——覆盖到板块级 + 已测点。经新端点 `GET /api/v1/knowledge-system` 暴露（**不动 17.x 画像契约**：画像维度键位白名单严格，板块覆盖走独立端点，不侵入既有画像）。
