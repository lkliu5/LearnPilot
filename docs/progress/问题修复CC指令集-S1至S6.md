## S3 — 流程重构（前端为主）｜问题 4、5、3-设置面板

> 核心：把"学情概览"从写死的展示页，改成"诊断后的真实产物 + 确认环节"，解决首登就有假数据的逻辑问题。

═══════════════════════════════════════════════════════════════
# 角色
资深前端工程师。项目已联调。本会话重构画像→学情概览的流程逻辑，并接入改密码。

# 背景
现状不合理：用户没做诊断，首登学情概览就显示了内容（Mock 假数据），评委一看即穿帮。

# 任务
1. **空状态门控（问题 4）**：未完成画像诊断时，学情概览**不显示任何数据**，改为引导态——"先完成画像诊断 →"，点击进诊断页。学情概览数据须来自真实 `GET /profile/student-portrait` / 诊断结果，无则视为未诊断。
2. **诊断完成确认弹窗（问题 5）**：对话诊断 `diagnosisComplete=true` 后，弹出「学情概况确认」弹窗，展示由**真实画像合成**的内容（6 维画像 + 知识雷达 + 优势/盲区）；底部「确认画像」按钮 → 确认后才正式生成学情概览并解锁学习路径。
3. **设置面板接改密码（问题 3）**：把 S1 的设置占位接入 S2 的 `/auth/change-password`，做改密码表单（旧/新/确认密码 + 校验提示）。

# 约束
Dashboard 数据改为读真实接口（替换硬编码 radar/strong/weak）；复用现有弹窗/雷达/卡片组件；不改后端逻辑（除调用 S2 接口）。

# 验证
①全新用户首登学情概览为引导态、无假数据；②走完诊断→确认弹窗出现且数据来自真实画像→点确认后学情概览才有内容；③改密码表单可成功改密；④`tsc` 干净、0 控制台错误。

# 输出
文件清单 + 验证结果。完成即停。

# 任务
1. **后端**：新增「课程资料 ingest」能力，**复用现有知识库管理模块**的 chunk + embedding + Chroma 入库逻辑；接收上传的 PDF/PPT/文本或大纲，按课程命名空间入库；提供处理状态查询（处理中/完成/失败）。接口须新增到接口文档并套信封。

## S6 — 视频按主题生成（跨栈）｜问题 9

> 确认：当前视频是 Remotion 写死的神经网络场景，未接 LLM。需脚本生成 + composition 参数化两步。

═══════════════════════════════════════════════════════════════
# 角色
资深全栈工程师。项目已联调。本会话让讲解视频内容随知识点动态生成，不再固定为神经网络。

# 任务
1. **后端**：新增/改造视频脚本生成——用 LLM（现有默认模型 deepseek，**无需星火**）根据当前知识点生成**视频分镜脚本**（标题、3–5 个场景的要点文本与旁白）；结构化返回，套信封；Mock 与真实双模式。
2. **前端**：把 `LectureVideo.tsx` 的**写死场景改为参数化通用模板**——接收后端返回的分镜脚本作为 props 渲染（场景标题/要点/旁白随数据变）；旁白沿用现有 TTS 演示方案。`/resource/video` 返回的内容须对应当前知识点。

# 约束
不破坏 Remotion 渲染管线与播放器；通用模板要能容纳不同主题的脚本；保留无脚本时的兜底。

# 验证
对两个不同知识点（如"Transformer"与"二叉树"）各生成视频→**画面与旁白内容确实不同**、对应各自主题，不再都是神经网络。

# 输出
