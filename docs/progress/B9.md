## 二、接口契约（接口文档第 16 章，4 个新接口）

| 接口 | 方法 | 鉴权 | 关键约束 |
|---|---|---|---|
| `/auth/register` | POST | 公开 | 查重/弱密码(<6) → 1001；成功返回 login 同构 token+user，role=learner、未诊断 |
| `/admin/users` | GET | admin | 分页；行含 userId/username/role/isActive/hasDiagnosed/passedKpCount/createdAt/lastActiveAt |
| `/admin/users/{id}/reset-progress` | POST | admin | 清空 Mastery+复位 Journey（幂等）；目标 admin → 1003；不存在 → 1004 |
| `/admin/users/{id}/toggle-active` | POST | admin | 翻转 isActive；目标 admin → 1003；不存在 → 1004 |
| `/auth/login`（增补 16.0） | POST | 公开 | 禁用账号 → 1002「账号已禁用」；成功刷新 lastActiveAt |

## 五、诚实声明与边界

1. **新增章节编号**：执行方案要求「追加第 15 章」，但接口文档第 15 章已被 V1.1 字段补丁占用，故 B9 新接口另起**第 16 章**（语义不变，已在章首注明），未触碰既有 15 章内容。
2. **禁用账号错误码用 1002**：按本阶段指令「被禁用账号登录返回 1002」，复用既有「未认证」码位（语义上属「不予签发凭据」）；前端 `api.ts` 对 1002 既有的清票/刷新逻辑未改动，禁用登录与口令错误表现一致（均被拦在登录页）。
3. **修改了已验收阶段文件**：`entities.py`（加两列）、`init_db.py`（加迁移）、`auth.py`（抽 helper + 禁用拦截/活跃刷新 + 注册）、`main.py`（挂路由）、`Login.tsx`/`App.tsx`/`Sidebar.tsx`（注册入口与用户管理导航）——均为本阶段新功能所需，**无既有接口契约字段变更**；既有 107 条用例零回归。
4. **前端业务逻辑改动已最小化并单列**：仅为承载 B9 新功能的必要改动（注册入口/用户管理页/导航与路由守卫），未触碰 Zustand store 结构与既有页面业务逻辑；mock 模式（USE_REAL_API=false）登录/注册回退演示路径不破坏。
5. **最近活跃口径**：`lastActiveAt` = 最近一次登录成功时间（注册即首次登录）；非「每次请求刷新」，避免每请求写库。生产可按需细化。
