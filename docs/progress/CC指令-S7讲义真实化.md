# 角色
资深后端工程师（FastAPI + LangGraph + Chroma + RAG）。项目已联调，禁止改动既有接口签名。本会话把讲义生成从 Mock 切到真实多智能体管线。

# 任务 1：先查现状（必做，先报告再决定）
查清并在回复中说明：
1. `/resource/lecture` 当前返回的讲义是**写死的**（如 lectureByLevel 3 档固定文本、sources 固定、幻觉率固定 `<5%`），还是真实生成的？
2. 项目里是否已存在真实的 **RAG 检索 + 生成 Agent + 审核 Agent** 管线（即产出指标报告所用的那套）？在哪个模块/服务？
若 `/resource/lecture` 已是真实生成，报告确认后跳过任务 2。

# 任务 2：接真实管线（若现状为 Mock）
把 `/resource/lecture` 接到真实管线，按知识点 + 难度生成讲义：
- **真实 RAG 检索**：从 Chroma 检索相关文档片段（复用现有 retriever）；
- **生成 Agent**：基于检索内容生成讲义正文（经 LLMClient，**默认模型即可，无需星火**）；
- **审核 Agent（Critic）**：逐句接地校验、计算**真实幻觉率**，超阈值触发重试/降级（复用现有审核逻辑）；
- **返回真实数据**：讲义正文 + **真实 sources**（可溯源到具体检索文档片段）+ **真实计算的幻觉率**（不再是固定 `<5%`）。
- **保留 Mock 模式**：无密钥时走占位讲义可跑通；演示稳定性优先。
- 沿用讲义缓存（ResourceCache，按 kp+难度+provider 隔离），首次生成后命中缓存。

# 约束
- **复用已有 RAG/Agent/审核管线**（产出指标报告那套），不要重建一套。
- `/resource/lecture` 请求/响应的**字段名与层级保持不变**，只换数据来源与真实度；溯源徽章前端已有，sources 结构对齐现有契约。
- 不改其他接口；不动前端（除非接口字段确有缺口需前端适配，若有请单独说明）。

# 验证（实测并贴结果）
1. 同一知识点 + 难度生成真实讲义：**sources 来自真实检索**（能对上具体文档片段）、**幻觉率是真实计算值**（非固定 `<5%`）；
2. 入门 / 初级 / 高级三档生成内容**深度确有差异**；
3. 真实模式幻觉率仍**达标 < 5%**（贴出实测值）；
4. Mock 模式无密钥仍可跑通；
5. 全量测试通过、既有接口回归未变。
