## 会话一 · 画像诊断重构：从"自我报告"升级为"诊断测评"

═══════════════════════════════════════════════════════════════
# 角色
资深全栈工程师 + 测评设计。项目已联调，禁改既有接口签名。本会话重构画像诊断。

# 核心问题（要解决的）
1. 现画像靠"自我报告"——用户会说谎、隐瞒、甚至不了解自己，测不准真实水平；
2. 六维太笼统，且把"能力"（有高低，可打分）和"偏好/风格"（只有类型，无高低）混在同一个 0-100 雷达轴上，逻辑错乱（"学习节奏"哪有满分？）；
3. 诊断应"有选择性地抛出选择/题目"（类似 AI 问答的引导式），用行为反推真实水平，而非开放式自陈。

# 先查并报告
当前画像诊断（DialogueDiagnosticAgent / ProfileBuilder / 雷达图）：六维怎么采集的？是不是纯对话自陈？雷达图是不是六维全打 0-100 分？现有 quiz 题库（每知识点 10 题，含难度）能否复用作诊断微测来源？

# 重构设计（关键）

## 1. 把画像拆成三类，各用各的测法
- **能力画像（客观测，打分 0-100 + 依据）**：知识基础、各知识点掌握度。**不靠自陈**，用"诊断微测"测出来。
- **偏好画像（归类型，不打分）**：认知风格（图像型/文字型/案例型…）、学习节奏（快速概览型/稳步细钻型）、易错倾向（概念混淆/计算粗心…）。用"偏好选择题"归类，**不要放进 0-100 打分轴**。
- **主观信息（对话采集，描述性）**：学习目标、先验经验。对话中自然获取，不强行打分。

## 2. 诊断改为三段式（替代纯聊天自陈）
- **① 对话开场**：了解目标 / 先验经验等主观信息（保留现有对话能力）；
- **② 诊断微测（新增·核心）**：穿插 3-5 道由浅入深的选择/判断题（**优先复用现有 quiz 题库**按难度升序取题），根据答对情况**反推真实能力画像**——学生说"我懂"，就出题验证，用行为代替自陈；
- **③ 偏好选择题（改造）**：几道"你更喜欢哪种"的二/三选一（如"遇到新概念，你更想先看一张图 / 先读定义 / 先看一个例子？"），从选择**归类偏好画像**，不打分。

## 3. 能力画像每维带"依据"，可解释、防臆造
- 能力分必须能说明来源（基于哪几道题、哪些回答得出），无作答则标"未测/低置信"，不臆造高分。
- 诊断微测得到的是**初始能力基线**；后续阶段测试/quiz 继续更新掌握度——两者口径统一，不要造成两个互相打架的能力来源。

## 4. 雷达图/画像呈现重构
- **能力维度**：用打分雷达呈现（知识基础 + 各知识点掌握度），"当前能力 vs 目标能力"只对能力维度有意义；
- **偏好维度**：改用**类型标签/图标**呈现（如"🖼 图像型学习者 · 稳步细钻 · 易概念混淆"），**不再混进 0-100 雷达轴**——这是修复"雷达图别扭"的关键。

## 5. 沿用现有覆盖机制
- 三条路径（对话/简历/手动）统一产出这套新画像结构；重做诊断**覆盖更新**、刷新概览（复用现有 PUT /profile/student-portrait 覆盖语义）。

# 约束
- 不改既有接口签名（画像结构如需扩展，向后兼容或追加字段 + 同步文档）；**下游读画像的地方（学情概览/工作流诊断等）要同步适配新结构、不许回归**；
- 复用现有 quiz 题库作诊断微测来源、复用对话能力；Mock 兜底（无 Key 微测/偏好用确定性合成）。

# 验证（必须两用户对比 + 行为驱动）
1. **能力靠测不靠说**：同一用户诊断微测答得好 vs 答得差 → 能力画像分数明显不同、且带依据；空作答 → 标未测/低置信、不臆造；
2. **偏好归类型不打分**：偏好选择不同 → 偏好画像类型不同；偏好维度不出现在 0-100 打分轴；
3. **两用户对比**：用户A（AI 基础好 + 选图像型）vs 用户B（零基础 + 选细节型）→ 能力画像、偏好画像都明显不同；
4. 雷达图：能力维度打分、偏好维度类型标签，呈现清晰不混轴；
5. 重做诊断覆盖刷新概览；下游（概览/工作流诊断）读新画像无回归；全量测试通过、tsc 干净。

# 输出
现状说明 + 画像新结构说明 + 改动文件清单 + 接口文档增量 + 5 项验证结果（含两用户对比数据）+ 红线自检。完成即停。

## 会话二 · 学习路径真个性化（依赖会话一的新画像）

> 会话一验证通过后再跑。

═══════════════════════════════════════════════════════════════
# 角色
资深全栈工程师。项目已联调，禁改既有接口签名。本会话让学习路径真正因画像而变。

# 核心问题
现路径"写死"——画像怎么变，路径节点和顺序都不变，个性化没体现。

# 先查并报告（定位写死在哪层）
1. planner_agent 现在到底有没有读**当前用户的真实画像 + 掌握度**？还是用了默认值/固定输入（类比之前工作流诊断写死那种 bug）？
2. 会话一改了画像结构后，planner 的输入是否还停留在旧画像、没接上新的"能力 + 偏好"画像？
3. 前端展示的路径是后端 planner 真算的，还是前端写死一套静态的？
报告定位结论：写死在 planner 输入 / planner 逻辑 / 前端展示 哪一层。

# 个性化要体现在两个维度（关键设计）
- **能力画像 → 决定"学什么、什么顺序"**：薄弱知识点优先、已掌握的跳过/后置。两个不同基础的学生，**路径的节点与顺序必须不同**（零基础从头学，基础好直奔进阶）。
- **偏好画像 → 决定"每一步怎么学"**：同一知识点，路径节点默认推荐的**资源形式因人而异**——图像型默认推图解、细钻型推详细讲义、概览型先推思维导图。

# 任务
1. 让 planner **真消费会话一的能力画像**：按真实掌握度/薄弱点动态生成路径的**节点与顺序**；
2. 让路径**每个节点消费偏好画像**：节点默认推荐的资源形式/粒度按认知风格、学习节奏因人而异；
3. **画像变 → 路径跟着变**：重做诊断、画像更新后，路径相应重算（不缓存写死）；
4. 在路径界面适当呈现"为你这样规划的理由"（如"因你 X 薄弱，优先安排 Y"），让个性化可感知、可解释。

# 约束
复用现有 planner / 资源类型 / 画像；不改既有接口签名（新增仅追加并同步文档）；Mock 兜底；不破坏会话一画像与下游一致性。

# 验证（必须两个对比鲜明的学生）
1. 用户A（AI 基础好 + 图像型）vs 用户B（零基础 + 细节型）→ 跑出的路径：**节点不同、顺序不同、各节点默认推荐的资源形式也不同**（贴两条路径对比）；
2. **画像变路径变**：把某用户画像从"零基础"改成"基础好"重做 → 路径明显改变（不再写死）；
3. 路径界面有"规划理由"、个性化可感知；
4. 既有接口零回归、全量测试通过、tsc 干净。

# 输出
定位结论 + 改动文件清单 + 接口文档增量 + 4 项验证结果（含两用户路径对比）+ 红线自检。完成即停。
