## S6 — 讲解视频按主题生成（跨栈会话）

> 确认过的根因：`LectureVideo.tsx` 是写死的神经网络场景、未接 LLM，所以任何主题都渲出同一个视频。需"脚本生成 + composition 参数化"两步，缺一不可。

═══════════════════════════════════════════════════════════════
# 角色
资深全栈工程师（后端 FastAPI + LangGraph；前端 React + Remotion）。项目已联调。本会话让讲解视频内容随知识点动态生成，不再固定为神经网络。

# 背景
当前视频画面/旁白是 Remotion 里硬编码的 5 个神经网络场景，与所学主题无关。

# 任务
1. **后端**：新增/改造视频脚本生成——用现有默认模型（deepseek，**无需星火**）按当前知识点生成**结构化分镜脚本**：标题 + 3–5 个场景，每场景含 `要点文本` 与 `旁白`。经 `LLMClient` 适配层，Mock 与真实双模式（Mock 给与主题相关的占位脚本，而非神经网络）。`/resource/video`（或其脚本子接口）返回该脚本，套统一信封；**响应若新增字段，同步追加进接口文档**。
2. **前端**：把 `LectureVideo.tsx` 的写死场景改成**参数化通用模板**——接收后端分镜脚本作为 props，场景标题/要点/旁白随数据渲染；保留 Remotion 渲染管线与现有 TTS 旁白演示方案；无脚本时给兜底占位。

# 约束
不破坏 Remotion 播放/渲染管线；通用模板需能容纳不同主题、不同场景数；不改其他既有接口签名。

# 验证（关键，必须实测对比）
对**两个差异明显的知识点**（如「Transformer 注意力机制」与「二叉树遍历」）各生成一次视频，确认：
- 画面场景标题/要点**内容确实不同**、各自对应主题；
- 旁白文本不同；
- **不再都是神经网络**。
贴出两个主题各自生成脚本的关键差异片段。

# 输出
