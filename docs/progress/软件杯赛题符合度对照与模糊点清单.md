# 软件杯赛题要求符合度对照 & 模糊点清单

**对照日期：** 2026-06-15
**对照依据：** 官方《赛题要求.txt》 vs 当前项目（开发文档 / 接口文档 / 指标报告）
**状态图例：** ✅ 满足 ｜ ⚠️ 部分满足 / 需加强 ｜ ❌ 不满足 / 偏离要求 ｜ ❓ 模糊点（建议澄清）

> **总体结论**：项目在多智能体架构、多模态资源、防幻觉、界面体验上完成度高；但有 **1 项核心功能与赛题措辞直接冲突（对话式画像）**，多项底层仍为 Mock，且存在 **若干必须澄清的合规模糊点（尤其"科大讯飞工具"约束、视频时长、画像维度定义）**。功能实现与技术要求占 45%、创新与实用占 35%，下列不达标项多集中在这两块，需优先处理。

---

## 一、核心功能需求对照（占评分大头）

### 功能 1 · 对话式学习画像自主构建 — ❌ 与要求直接冲突

| 赛题要求 | 项目现状 | 判定 |
|---|---|---|
| **摒弃传统繁琐表单** | 当前主流程恰恰是多步**表单**：单选按钮 + 12 知识点滑块自评 | ❌ 直接违反 |
| 通过**自然语言对话**自动抽取特征 | 画像构建环节无对话；苏格拉底对话仅用于资源页答疑，未用于诊断 | ❌ 缺失 |
| 不少于 **6 个维度**（知识基础 / 认知风格 / 易错点偏好等） | 有 6 维，但 **6 维全是"知识点掌握度"**，缺认知风格、易错点偏好等异质维度 | ⚠️ 维度数量够、维度类型不符 |
| 画像**随学随新** | 有错题→画像更新闭环 | ✅ |

> **这是最严重的不达标项**——赛题标题就叫"对话式…自主构建"，并明确"摒弃表单"，而项目主交互是表单自评。**必须补一条对话式诊断主路径**（可复用 SocraticTutor 框架），并把画像维度扩展为含认知风格/易错点等异质维度。

### 功能 2 · 多智能体协同的资源生成 — ⚠️ 数量达标，真实性存疑

| 赛题要求 | 项目现状 | 判定 |
|---|---|---|
| 体现"多智能体"架构 | 诊断 / 生成 / 审核三 Agent + LangGraph | ✅ |
| **至少 5 种**资源类型 | 讲义 / 思维导图 / Mermaid 图解 / 代码沙箱 / 视频 / 测验 / 外部资源（≥7 种） | ✅ 数量满足 |
| 由**不同角色智能体协作**完成生成 | 多数模态当前是前端 Mock 直出，未真正经智能体协作生成 | ⚠️ 需切真实（见 Mock 清单） |

### 功能 3 · 个性化学习路径规划与资源推送 — ⚠️ 界面有，底层 Mock

| 赛题要求 | 项目现状 | 判定 |
|---|---|---|
| 动态规划学习路径、明确步骤顺序 | LearningPath 页（时间线 / 卡片双视图）已完成 | ✅ 界面 |
| 多智能体协同生成路径 | `/learning-path/generate` 当前 Mock 1.5s 假完成 | ⚠️ 切真实规划 Agent |
| 基于画像**精准推送**资源 | 有推送雏形，但与画像联动较弱 | ⚠️ 加强画像驱动推送 |

### 功能 4 · 智能辅导（可选加分项）— ⚠️ 文字够，多模态弱

| 赛题要求 | 项目现状 | 判定 |
|---|---|---|
| 即时答疑 | 苏格拉底导学对话 | ✅（当前本地匹配，需切真实 Agent + SSE） |
| **多模态**答疑（文字 + 图解 + 短视频讲解） | 当前仅文字对话，无图解 / 短视频形式的即时答疑 | ⚠️ 可补多模态答疑形式 |

### 功能 5 · 学习效果评估（可选加分项）— ⚠️ 评估有，行为跟踪弱

| 赛题要求 | 项目现状 | 判定 |
|---|---|---|
| 多维度精准评估 | 测验判分 + 错题诊断 + Dashboard 学情概览 | ✅（部分 Mock） |
| 实时跟踪**学习行为 / 资源使用反馈** | 缺行为埋点与资源使用数据采集 | ⚠️ 缺数据采集层 |
| 根据评估动态调整推送策略 | 有错题驱动再生成，策略调整较局部 | ⚠️ 可加强闭环 |

## 五、模糊点清单（建议尽快向蒋老师 / 主办方澄清）❓

> 以下为赛题措辞不明确、或与内部口径 / 现状冲突，会直接影响合规与评分的点。

1. **"科大讯飞相关工具"约束的边界（最高优先级）**
   赛题简介举例可用"AI 辅助编程工具（如 Claude Code 等）"，但实现条件又写"其他 AI 辅助工具需选用科大讯飞相关工具"。需澄清：
   - 底层推理大模型是否**必须**用星火？当前用 deepseek 是否合规？
   - "AI 辅助工具"指编程工具、还是也含运行时调用的大模型？
   - （会议口头说过"星火加分但不强制、可用更强模型"，但与赛题正式文档表述不一致，需以书面确认为准。）

2. **"摒弃传统繁琐表单"的尺度**
   是完全不允许表单，还是"对话为主、表单为辅"可接受？这决定画像模块要重构到什么程度。

3. **画像"6 个维度"的定义**
   是指 6 个知识点掌握度，还是 6 个**异质维度**（知识基础 / 认知风格 / 易错点偏好…）？赛题举例倾向后者，项目当前是前者，口径不同则可能判不达标。

4. **"至少 5 种资源类型"是否要求每种均由智能体真实生成**
   当前部分模态为 Mock 直出。Mock 资源能否计入"智能体协作生成的 5 种"，需确认评审口径（建议核心几种务必切真实）。

5. **"多模态生成大模型"的要求强度**
   赛题简介点名 SeeDance 类多模态生成大模型；项目视频用 Remotion（代码生成）而非多模态生成模型。需确认是否必须接入真正的多模态生成大模型，还是 Remotion 方案可接受。

6. **演示视频时长**
   赛题 7 分钟 vs 内部 10 分钟——确认以 7 分钟为准并据此重剪。
