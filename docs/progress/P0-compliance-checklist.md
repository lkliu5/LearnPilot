## A — 内容安全过滤机制（CC，先查现状）

> 这是赛题明列、最可能是真缺口的一项。防幻觉已做，但"无敏感违规信息"的内容安全过滤多半没做。

```
# 角色
资深后端工程师。项目已联调，禁止改既有接口签名。本会话补内容安全过滤机制。

# 任务 1：先查现状（先报告）
查清：现有对生成内容是否有任何敏感/违规过滤？防幻觉(Critic)只管事实性，不等于内容安全。若已有，报告确认后跳过。

# 任务 2：若缺，补轻量内容安全过滤层
- 在所有 LLM 生成内容返回前过一道内容安全检测（讲义/对话诊断/费曼/线索/图解等统一经过）：检测政治敏感、暴力、违法、不良信息等；命中则拦截或脱敏 + 返回降级提示，套统一信封错误/提示口径。
- 实现为可复用中间件/服务，敏感词表可配；预留可选的模型级二次校验开关。
- Mock/真实双模式；不改接口签名（仅在输出环节加过滤）。

# 验证
注入测试敏感内容→被拦截/脱敏；正常学术内容→照常通过；既有接口回归未变、全量测试通过。

# 输出
现状说明 + 改动文件清单 + 验证结果 + 红线自检。完成即停。
```

## B — 开源依赖 + 协议标注（CC，快）

```
# 角色
工程师。本会话生成开源依赖与协议清单文档，不改业务代码。

# 任务
- 扫描 frontend/package.json + backend/requirements.txt（及 lock 文件），生成《开源依赖与协议清单》(docs/开源依赖与协议.md)：每项含 名称/版本/用途/来源/License 类型。
- 标注前沿 AI 工具/框架（LangGraph/Remotion/Sandpack/bge/Chroma 等）的名称、来源、协议。
- 标记任何 copyleft（GPL/AGPL 等）依赖供人工复核。

# 输出
docs/开源依赖与协议.md + 简要风险提示（如有 copyleft）。完成即停。
```

---

## C — AI Coding 工具说明（CC 辅助草稿，人工补真实比例）

```
# 角色
工程师。本会话生成 AI 辅助开发说明文档草稿，不改业务代码。

# 任务
- 生成《AI 辅助开发说明》(docs/AI辅助开发说明.md) 结构：使用的 AI 编程工具（Claude Code 等）、各模块的 AI 生成/人工审核大致占比、AI 与人工分工。
- 用 git log/commit 统计辅助估算（commit 数、改动行数）作为参考数据填入，并明确标注"需人工核对真实比例"的占位。
- 如赛题"其他 AI 辅助工具需用科大讯飞相关工具"涉及，按实际使用情况如实说明（底层模型为 deepseek，编程工具为 Claude Code 等）。

# 输出
docs/AI辅助开发说明.md（含 git 统计参考 + 待人工确认占位）。完成即停。
```

## D — 系统/测试说明书收口（CC 辅助）

把已有的大量进度文档(docs/progress/*)、接口文档、指标报告，整理成赛题要求的标准《系统开发说明书》《测试说明书》骨架（需求分析→架构→功能实现→测试→部署），CC 可生成目录与各章占位+把现有内容归位，人工补润色。可作为单独会话。

---

## E / F — 演示视频(≤7min) + PPT（人工为主，CC 可辅助）

- **视频脚本/分镜**：CC 可帮写一份 7 分钟演示脚本（钩子→痛点→技术亮点→核心功能演示→闭环故事→指标收尾），人工照脚本录屏剪辑。务必 ≤7 分钟。
- **PPT 大纲**：CC 可帮写大纲与每页要点（应用价值/前沿 AI 融合思路/创新/核心功能），人工做视觉。
- 需要的话单独开会话让我出脚本和大纲。

---

## 推荐冲刺顺序
```
1. A 内容安全过滤（先查——若缺是硬要求，优先补）
2. B 开源协议清单 + C AI Coding 说明（CC 快速产出，必交）
3. D 文档收口（CC 辅助生成骨架，人工润色）
4. E 视频脚本 + F PPT 大纲（CC 出稿）→ 人工录制/制作（留足时间）
```

> 判断：A 是唯一可能"功能缺失"的硬要求，先查先补；B/C 是"必交但快"，CC 半天出稿；E/F 最花时间且占 10%，脚本/大纲让 CC 先出，人工尽早开始录制。
