## 会话一 · 岗位匹配中度弱化 + 诊断/概览理顺

═══════════════════════════════════════════════════════════════
# 角色
资深全栈工程师。项目已联调，禁改既有接口签名。本会话弱化岗位匹配、理顺被它搅乱的诊断/概览逻辑。

# 背景
岗位匹配（/job-market/match 等）当初为"目标量化"接进了诊断/学情概览，但把诊断与概览的信息逻辑搅乱了。现产品主线收敛到"个性化资源生成 + 实时辅导"，岗位匹配**降级为轻量可选模块**，不再作为诊断/概览主信息。**保留功能、不删接口**，只降权与理顺。

# 任务
1. **先查并报告**：岗位匹配目前在诊断流程 / 学情概览 / 大屏等哪些地方作为主信息出现？它的存在让哪些信息逻辑变乱（口径不一致、目标岗位信息来源混乱等）？
2. **降权**：把岗位匹配从诊断确认 / 学情概览的**主信息位**摘出，降为一个**可选的轻量小模块/折叠项**（保留入口，但不占主视觉、不参与主叙事）。
3. **理顺诊断/概览**：移除岗位匹配带来的逻辑耦合，让对话画像 → 学情概览的信息回到**干净一致**的状态（概览聚焦真实画像 + 掌握度 + 学习评估，不被岗位信息干扰）。
4. 后端接口**保留**（/job-market/* 仍可用），仅前端降权 + 必要的逻辑解耦；不删数据、不改签名。

# 验证
1. 诊断/学情概览不再以岗位匹配为主信息，信息口径干净一致；
2. 岗位匹配作为可选轻量模块仍可访问、功能正常；
3. 既有接口零回归、全量测试通过、tsc 干净。

# 输出
现状说明 + 改动文件清单 + 验证结果 + 红线自检。完成即停。

## 会话二 · 即时辅导：显眼常驻 + 实时反馈三件套

═══════════════════════════════════════════════════════════════
# 角色
资深前端工程师。项目已联调，禁改既有接口签名。本会话把"即时辅导"做成核心常驻功能，并强化实时反馈体感。复用现有 /resource/tutor/suggest + /generate + 苏格拉底 SSE 流式接口，不改后端签名。

# 背景
"学习中遇到问题 → 实时反馈 → 针对性生成资源"是本系统最具创新性的交互（评委高度认可）。要做到：入口显眼常驻 + 反馈足够"实时主动"。

# 任务

## A. 显眼常驻入口 + 改名
- 把原「🆘我没懂」统一改为「**即时辅导**」，去掉被动求助感。
- 在学习内容区（讲义/视频阅读旁）放**醒目的常驻入口**（固定辅助工具条/侧边按钮，套设计令牌），不再藏在面板底部。
- **不与"去通关"主按钮抢焦点**：去通关仍是全页主操作，即时辅导是显眼的次级常驻辅助。

## B. 实时反馈三件套（叠加，构成"AI 实时在帮我"的体感）
1. **流式实时回答**：即时辅导的问题识别 / 答疑回答改为**SSE 流式逐字呈现**（复用现有苏格拉底 tutor_chat_stream 流式能力），不要转圈等待后整坨返回。
2. **选中讲义提问**：讲义阅读时，用户**选中一段文字**即可弹出"就这段问 AI"的快捷操作，直接把选中内容作为问题发起即时辅导，让"针对性"具体到句子。
3. **主动察觉卡顿**：当学习行为出现"卡住信号"（如同一知识点反复查看、测验出错、停留时长异常）时，AI **主动**弹出轻量关怀提示（"这块是不是有点难？要我帮你讲讲吗？"），点击即进入即时辅导。信号判定用现有可得的行为数据（quiz 错题 / 步骤停留 / 重复访问），阈值合理、**不要频繁打扰**（同一会话/知识点限频）。

## 约束
复用现有 tutor suggest/generate + 苏格拉底 SSE + 行为数据（QuizAttempt/步骤进度）；不改后端签名（如需新增仅追加并同步文档）；深浅主题正常；mock 兜底。

# 验证（截图）
1. 学习界面有显眼常驻「即时辅导」入口（非底部小按钮）；
2. 流式：辅导回答逐字实时蹦出（非整坨等待）；
3. 选中讲义文字 → 出现"就这段问 AI" → 能就该句发起辅导并生成资源；
4. 主动卡顿提示：构造卡住信号（连续答错/反复看同一点）→ AI 主动弹关怀提示、限频不打扰；
5. 不与"去通关"抢焦点；既有链路（识别问题→清单→生成、视频走 Remotion 自然语音）仍正常；tsc 干净、0 console error。

# 输出
现状说明 + 改动文件清单 + 接口文档增量（如有）+ 验证结果 + 红线自检。完成即停。
