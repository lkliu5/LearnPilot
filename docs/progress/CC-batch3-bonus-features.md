## 批3-A — 学习过程评估 Agent（需求 2 · 赛题功能 5）

═══════════════════════════════════════════════════════════════
# 角色
资深全栈工程师。项目已联调，禁止改既有接口签名。本会话新增"学习过程评估"能力。

# 任务 1：先查现状
查清：现有是否有**专门的学习评估 Agent**？是否有**学习行为跟踪数据**（资源使用 / 停留 / 做题历史 / 进度事件）？学情概览目前只是聚合掌握度，不算过程评估。

# 任务 2：新增评估 Agent + 行为数据 + UI
- **行为数据层**：采集/汇总可得的学习信号——做题表现（quiz 历史）、资源使用、进度推进、各步骤完成情况（复用既有 Mastery/Journey/quiz/steps 数据，缺的轻量补埋点）。

- **UI 体现**：在学情概览新增**"学习评估"卡/面板**，展示多维评估 + 建议（赛题要求"在界面中体现"）。

# 验证
评估接口基于真实做题/进度数据产出因人而异的多维评估；UI 出现评估卡；mock 可跑；既有接口回归未变、全量测试通过。

# 输出

## 批3-B — 智能辅导按需资源生成（需求 1 · 赛题功能 4）

═══════════════════════════════════════════════════════════════
# 角色
资深全栈工程师。项目已联调，禁止改既有接口签名。本会话新增"智能辅导·按需资源生成"。

# 任务
- 学生在学习中遇到问题时（导学对话里提问、或点"我没懂"），系统**识别问题点**，返回一份**针对性资源生成清单**——例如"针对这个盲区可生成：①知识图解 ②例题 ③短视频讲解 ④补充讲义片段"，每项标注类型与预计内容。

## 批3-C — 学习资源 AI 联网搜索（问题 7 · 外部资源聚合真实化）

> ⚠️ 此项依赖**联网搜索能力**——需要一个搜索 API / 服务。先查现状，并把搜索源设计成**可插拔 + mock 兜底**。

═══════════════════════════════════════════════════════════════
# 角色
资深全栈工程师。项目已联调，禁止改既有接口签名。本会话把"资源推荐"从静态种子库改为 AI 联网搜索聚合。

# 任务 1：先查现状 + 确认搜索能力
- 查清 `/resource/external` 当前实现（应为静态种子库）。
- 确认可用的**联网搜索方式**（是否已配置某搜索 API / 可用的 YouTube/B站/arXiv 接口）；**若无现成能力，把搜索源抽象成可插拔 provider 接口、并以 mock provider 兜底**，在回复中说明需要人工提供哪种搜索 API。

# 任务 2：联网聚合 Agent
- 按当前知识点 + 用户画像/薄弱点，**联网搜索**相关优质资源（视频/论文/开源项目等），经**聚合 Agent 整理 + critic 评分**返回带相关度/可信度的清单；后端代理避配额/跨域。
- 放进**资源生成/资源推荐区**；无搜索能力时走 mock provider 返回占位、保证可跑。

# 约束
搜索源可插拔（接口 + mock 兜底）；不改既有接口签名（新增仅追加并同步文档）；保留 mock。

# 验证
配置搜索能力时返回真实联网结果（贴几条）；无能力时 mock 兜底可跑；既有接口回归未变、全量测试通过。

# 输出
现状说明 + 搜索能力确认 + 文件清单 + 接口文档增量 + 验证结果 + 红线自检。完成即停。
